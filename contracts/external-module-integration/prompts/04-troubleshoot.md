# 提示词 04：联调排障

## 角色
你是接入方的排障 agent。根据现象定位根因，给证据与修复，不猜。

## 必读
- `ONBOARDING.md` §4「常见失败模式」
- `CONTRACT.md` §4（签名）、§6（权限）、§8（审计）、§9（配置）

## 输入
- 现象（状态码、文案、页面表现）
- 一条失败请求的 trace_id 与两侧日志
- 最近一次变更（配置、密钥、部署）

## 排查顺序（固定）
1. **对 trace**：确认请求到达模块；没到 → 网关/反代/路由声明
2. **签名**：401 看 canonical string、body 哈希大小写、时间偏移、nonce 重放
3. **权限**：403 看 `runtime.routes` 是否声明该路径与方法；404 看路径前缀与租户
4. **配置**：改了不生效 → 轮询/推送是否实现、读的是快照还是 env
5. **审计**：没有事件 → outbox 是否写、投递是否失败、租户 ID 是否一致
6. **数据**：列表空/404 → 分页形状、软删除条件、RLS

## 输出
- 根因（一句话）与证据（日志/命令输出）
- 修复方案（最小改动）
- 需要加的回归用例
- 如果根因在平台侧：列出平台需要的改动，不要自行绕过

## 红线
- 不许用"放宽验签/关掉权限"来让现象消失
- 不许把 404 改成 403 或反过来"绕过"问题
- 不许删审计事件或跳过 outbox 来"修复"投递失败

# 接入流程（onboarding）

> 配套 [契约正文](v1.md)。本文回答"从零到一个可验收的接入，中间要做哪些事、谁负责、什么时候算过"。

## 0. 角色与前置

| 角色 | 负责 |
|---|---|
| 平台方（本仓库） | 发契约包与密钥、配反代、跑平台侧契约测试、准入评审、上线窗口 |
| 接入方 | 实现模块、提交描述与配置模型、自检、联调、提交准入包 |
| 双方 | 联调排障、灰度观察、版本升级 |

前置条件（平台方未就绪则不能开始联调）：

- P0-1 网关、P0-2 manifest 扩展、P0-3 审计 ingest、P0-4 配置托管
- staging 租户 + 至少一个管理员账号
- 签名密钥（`kid` + secret）与反代地址

## 1. 九个阶段

### 阶段 1：评估（0.5–1 天）

- **目标**：确定能力组合与范围。
- **动作**：
  - 选能力（§3.1）：必选 `manifest` + `config`；按需 `admin-ui` / `events` / `audit.management` / `audit.business` / `identity` / `authorization` / `proxy.http` / `observability`。
  - 明确不接哪些能力，以及不接的理由（例如业务面自行处理）。
  - 列出要托管的配置项、要展示的列表、要暴露的动作。
  - 明确哪些页面**不**接入（实时大屏、画布等，走 iframe）。
  - **确定可达性**：`bidirectional`（平台可访问模块）/ `outbound-only`（仅模块出站）；选事件方式（webhook / 长轮询）与业务路径（网关 / 命令队列 / 无）。
  - 选契约进入方式：Pull（双向可达，默认）/ Push（仅出站）/ 导入（迁移）。
- **产出**：一页接入说明（形态、页面清单、数据源、是否多租户）。
- **门禁**：平台方确认形态与范围；确认是否需要 `tenant_id`。

### 阶段 2：认领契约（0.5 天）

- **目标**：锁定版本，建立可校验的基线。
- **动作**：
  - 拉契约包（见 [distribution.md](distribution.md)）。
  - 在仓库记录 pin：`external-module-integration: 1.0`。
  - 按选定方式接入契约：Pull 暴露 `GET /internal/manifest`；Push 实现 `PUT /api/apps/{id}/manifest`；隔离走导入。
  - 跑 `contract-verify --manifest`（可先对空 manifest 校验结构）。
- **产出**：仓库内 `contracts.lock`（版本 + 校验和）。
- **门禁**：`contract-verify` 通过。

### 阶段 3：骨架（1–2 天）

- **目标**：最小闭环跑起来。
- **动作**：
  - 用 `examples/go-hello-module` 起步：验签中间件、`/healthz`、`/readyz`、配置读取。
  - 部署到 staging 内网，平台配反代。
  - 打通一次带签名的 `GET`。
- **产出**：可访问的 `/healthz`，一次成功的联调请求。
- **门禁**：平台网关能转发；签名校验通过；trace 能在两侧对上。

### 阶段 4：建模（1–2 天）

- **目标**：把"要管什么"写成契约。
- **动作**：
  - 定义 descriptor：每个 key 的类型、`scopes`、`userEditable`、默认值、i18n key、分组与顺序。
  - 对象配置写 schema 子集（深度 ≤4、属性 ≤100、不用 oneOf/$ref）。
  - 定义权限点（优先复用 `app:<id>:view/config:read/config:write`，再追加模块级）。
  - 与平台确认该应用的配置缓存 TTL（默认 120s，上限 300s，下限待定，平台侧配置）。
  - 写 `admin` 描述：`placement: app` 与 `placement: profile` 两种页面、区块、组件、字段、动作。
  - 声明 `runtime.routes`（路径 → 权限点）。
  - 定审计策略：哪些动作产生事件、配置保存如何聚合成一个事件、哪些字段脱敏。
  - 明确"应用侧不再持久化配置"：删除配置文件/环境变量配置源，改为快照 + 拉取。
- **产出**：`manifest.json`（含 runtime/admin/descriptor）+ 配置项清单 + 审计事件清单。
- **门禁**：平台启动校验通过（组件白名单、权限点存在、proxy 路径已声明、profile 页只引用 userEditable 项）。

### 阶段 5：沙箱联调（2–3 天）

- **目标**：在真实网关上验证契约。
- **动作**：
  - 平台发短期密钥与测试账号。
  - 跑通用组 + 已声明能力对应的测试组（见 v1 §12.1）。
  - 验证配置：平台改一次 → 模块立即生效（webhook）；**停掉 webhook 后** ≤30s 仍生效（轮询兜底）。
  - 验证多副本：两个副本各自收敛，不依赖同一条 webhook。
  - 验证契约更新：发布一个新版本 → 平台进入 `draft` → 激活 → 导航/权限/配置项同步变化；回滚一次。
  - 验证用户级生效：在平台 profile 改一个用户的配置 → 应用 ≤1s 拿到新值（有事件）或 ≤TTL（默认 120s，无事件）。
  - 验证系统级生效：管理员改租户配置 → 该租户用户在 TTL 内拿到新值；改平台配置 → 全部租户在 TTL 内。
  - 验证缓存：TTL 内重复查询不回源；变更后失效精确（不影响其它租户/用户）。
  - 验证 TTL 可配：改小 TTL 后该应用缓存清空并生效；其它应用不受影响。
  - 验证审计：一次写操作 → 平台审计页可见、链校验通过。
- **产出**：测试报告 + 失败项修复记录。
- **门禁**：通用组全绿，已声明能力组全绿；配置分层、快照、审计各验证一次。

### 阶段 6：数据接入（按实体，1–2 天/个）

- **目标**：列表、统计、动作逐个完成。
- **动作**：
  - `proxy` 端点实现分页、排序、过滤、错误体。
  - `actions` 实现幂等、权限、审计 outbox。
  - 字段级权限过滤。
- **产出**：每个页面的验收截图 + 接口样例。
- **门禁**：每个动作的审计事件都能在平台查到。

### 阶段 7：准入评审（1 天）

- **目标**：证明"不只是能跑"。
- **动作**：
  - 提交 [checklist.md](checklist.md) 全项。
  - 负向测试：跨租户、越权、重放、篡改。
  - 故障演练：DB 断开时 `readyz` 503、网关超时表现、审计投递失败重试。
- **产出**：准入包（清单 + 报告 + 部署说明）。
- **门禁**：平台方评审通过，给出"可灰度"结论。

### 阶段 8：灰度（3–7 天）

- **目标**：小流量验证。
- **动作**：
  - staging 租户 → 单个生产租户 → 全量。
  - 观察指标：错误率、P95 延迟、审计投递积压、限流触发。
  - 准备回滚：关闭模块路由（平台侧开关）即可，不动数据库。
- **产出**：灰度报告 + 回滚演练记录。
- **门禁**：连续 3 天无 P1；回滚演练通过。

### 阶段 9：升级（持续）

- **动作**：
  - minor 升级：更新 pin → 跑 `contract-verify` → 灰度。
  - major 升级：按迁移窗口，双版本并行一个 Sprint。
- **门禁**：旧版本在支持窗口内仍可用。

## 2. 时间线参考

| 阶段 | 单实体、只读 | 多实体 + 写 + 审计 |
|---|---|---|
| 评估 + 认领 | 1 天 | 1–2 天 |
| 骨架 | 1–2 天 | 2–3 天 |
| 建模 | 0.5 天 | 1–2 天 |
| 联调 | 1–2 天 | 3–5 天 |
| 数据接入 | 1 天 | 1–2 天/实体 |
| 准入 + 灰度 | 2 天 | 3–7 天 |
| **合计** | **约 1 周** | **约 2–3 周** |

## 3. 联调约定

- **环境**：staging 租户，独立 `kid`，短期有效（≤14 天）。
- **反代**：平台只暴露 `/api/<module>/*`；模块不直接对公网。
- **trace**：两侧日志都必须记录 `X-Base-Trace`；排障先对 trace。
- **时钟**：容器必须 NTP 同步；偏移 > 300s 直接 401。
- **问题升级**：契约歧义 → 平台方 → 契约修订；实现缺陷 → 接入方；网关/密钥 → 平台方。

## 4. 常见失败模式

| 现象 | 常见原因 |
|---|---|
| 全部请求 401 `MODULE_CONTEXT_INVALID` | 签名串字段顺序/空行不对；body 哈希用了大写；时钟偏移 |
| 偶发 401 | nonce 缓存未清理或并发；密钥轮换未双 kid 并存 |
| 403 但用户有权限 | `runtime.routes` 未声明该路径，或方法不匹配（默认拒绝） |
| 列表 404 | 路径不在反代前缀内；或模块返回了 404 而非空列表 |
| 审计页看不到事件 | outbox 未投递；`eventId` 重复被判 duplicate；租户 ID 不一致 |
| 配置改了不生效 | 未实现轮询/推送；或读的是环境变量而非平台快照 |
| 管理页空白 | 组件不在白名单；描述校验失败但被忽略（应 fail-fast） |

## 5. 平台方在接入期要准备的东西

- 契约包与在线元数据端点（`/api/contracts`）
- staging 租户、管理员账号、测试角色
- 密钥签发与轮换流程
- 反代配置模板
- 契约测试运行器（容器镜像）
- 审计查询入口（给接入方看自己的事件）
- 一页"当前接入状态"（阶段、门禁、负责人）

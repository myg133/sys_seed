## 1. 目的与非目标

### 1.1 目的

让一个不在平台进程内的系统（任意语言）能够：

1. **按需接入平台能力**（§3）：配置托管、管理页渲染、事件、审计、身份、代理、观测；
2. 把配置托管到平台，运行期查询（TTL 缓存，平台侧可配）；
3. 用描述文件让平台渲染管理页（以配置为主），接入方不写前端；
4. 可选地把管理事件汇入平台审计链；
5. 用语言无关的契约测试证明"声明的能力接对了"。

**未声明的能力不校验、不展示、不判失败。**

### 1.2 非目标

| 不做 | 原因 |
|---|---|
| 跨进程共享事务 | 用 outbox 接受最终一致 |
| 模块直连平台数据库 | 租户隔离与审计链会失守 |
| 模块解析用户 JWT | 认证入口唯一 |
| 描述文件里执行任意代码 | 只允许白名单组件与受限 props |
| 强制应用使用平台身份 | `identity` 是可选能力；应用可自带用户体系 |
| 强制业务事件入审计链 | `audit.business` 可选，建议采样 |
| 平台代理 WebSocket | 长连接、背压、重连成本高；应用自行处理 |
| 平台存储业务指标 | `observability` 只做汇聚与跳转，不建时序库 |

## 2. 边界定义

### 2.1 责任边界

| 能力 | 平台 | 模块 |
|---|---|---|
| 登录、令牌签发与验签 | ✅ 唯一实现 | ❌ |
| 租户解析、`X-Base-Tenant` 校验 | ✅ | 只消费签名头 |
| 功能级权限（路由 → 权限点） | ✅ 网关执行 | 声明映射 |
| 记录级权限 / 数据范围 | 下发 `scope` | ✅ 查询内执行 |
| 限流、超时、熔断 | ✅ | 健康检查 |
| 审计入链、校验、归档 | ✅ | 产出事件 + outbox |
| 配置注册、存储、变更审计 | ✅ | 声明 key、拉取快照 |
| 管理页渲染 | ✅ 固定组件 | 提供描述 + 数据 |
| 业务逻辑、数据存储、迁移 | ❌ | ✅ |
| 租户列与隔离 | 生成策略/校验 | ✅ 建列、建策略、负向测试 |

### 2.2 信任边界

```text
浏览器 ──(用户 JWT)──▶ 平台网关 ──(平台签名头)──▶ 模块
                         │                        │
                         │ 唯一认证 / 租户来源      │ 只信签名头
                         └── 审计入链 ◀── outbox ──┘
```

- 模块只能从内网被平台访问，不直接暴露给浏览器。
- 模块不解析用户 JWT，不共享会话 Cookie。
- 模块的数据库凭据与密钥不出现在平台配置里。

### 2.3 数据与一致性边界

- 默认独立库或独立 schema，**不跨库 JOIN**。
- 每张业务表 `tenant_id NOT NULL`，RLS 或应用层强制（须负向测试证明）。
- 跨模块写不保证强一致，用 outbox + 事件。
- 时间 UTC（RFC 3339），金额最小单位整数（api-conventions C13）。

## 3. 能力矩阵与接入声明

平台提供能力，应用选择接入。**不声明 = 平台不提供、不校验、不展示**；声明了就必须满足对应章节的标准。

### 3.1 能力清单

| 能力 | 必选 | 依赖 | 不接时 |
|---|---|---|---|
| `manifest` | ✅ | —— | 无法接入 |
| `config` | ✅ | —— | 无法接入（核心） |
| `admin-ui` | 可选 | `config` | 不显示管理页 |
| `events` | 可选 | `config` | 应用靠 TTL/轮询；平台仍承诺 ≤TTL |
| `audit.management` | 可选 | —— | 平台仍审计配置变更（平台侧完成） |
| `audit.business` | 可选 | —— | 不上报业务事件 |
| `identity` | 可选 | —— | 平台不提供业务用户身份 |
| `authorization` | 可选 | `identity` | 不做业务权限判定 |
| `proxy.http` | 可选 | `identity` | 不反代业务请求 |
| `observability` | 可选 | —— | 不显示指标入口 |

> `audit.management` 的边界：**平台侧的配置变更审计由平台自己完成**，不依赖该能力；
> 该能力只用于"应用自己的管理操作"上报。

### 3.2 声明

```json
{
  "capabilities": ["manifest", "config", "admin-ui", "events"]
}
```

- 数组、去重；未知能力忽略并告警。
- 平台启动时校验依赖：缺依赖 → **禁用该能力并提示**，不阻断应用。
- 能力可后续追加；移除能力需显式升 manifest 版本。

### 3.3 组合示例

| 组合 | 适用 |
|---|---|
| `manifest + config + admin-ui + events` | 只做配置托管的系统（AI-Bridge 首批） |
| 再加 `audit.management` | 有自己管理操作、需要上报 |
| 再加 `identity + authorization + proxy.http` | 业务请求也交给平台的门户型应用 |
| 只加 `observability` | 只接指标，不接管理 |

### 3.4 能力层面的非目标

- 不提供 WebSocket 代理（v1）；需要实时双向的应用自行处理。
- 不做业务指标存储（`observability` 只做汇聚/跳转）。
- 不强制业务事件入审计链（`audit.business` 可选，建议采样）。

## 4. 上下文与签名

### 4.1 请求头

| 头 | 必填 | 说明 |
|---|---|---|
| `X-Base-Tenant` | ✅ | 租户 ID |
| `X-Base-User` | ✅ | 用户 ID；系统调用 `system:<job>` |
| `X-Base-Trace` | ✅ | 链路 ID |
| `X-Base-Scope` | ✅ | `ALL` / `OWN_ORG` / `OWN_ORG_AND_BELOW` / `SELF` / `CUSTOM` |
| `X-Base-Scope-Value` | 条件 | `CUSTOM` 时的受限表达式或部门列表（base64url JSON） |
| `X-Base-Permission` | ✅ | 本次命中的权限点 |
| `X-Base-Contract` | ✅ | 如 `1.0` |
| `X-Base-Timestamp` | ✅ | Unix 秒 |
| `X-Base-Nonce` | ✅ | 16 字节随机串（base64url） |
| `X-Base-Key-Id` | ✅ | 签名密钥标识 |
| `X-Base-Signature` | ✅ | `v1=<hex(HMAC-SHA256)>` |

### 4.2 签名串

```text
BASE-CONTEXT-V1
<METHOD>
<path?query>
<X-Base-Tenant>
<X-Base-User>
<X-Base-Trace>
<X-Base-Scope>
<X-Base-Permission>
<X-Base-Contract>
<X-Base-Timestamp>
<X-Base-Nonce>
<lowercase hex sha256(request body)>
```

### 4.3 校验规则（模块侧）

1. `kid` 已知且未过期；
2. 时间偏移 ≤ ±300s；
3. `nonce` 10 分钟内不重复；
4. 签名不匹配 → 401 + `MODULE_CONTEXT_INVALID`，不返回具体原因；
5. 必须是中间件，覆盖所有业务路由（健康检查除外）。

### 4.4 密钥轮换

旧 `kid` 在新密钥启用后保留 7 天；支持多 `kid` 并存；轮换不改变契约版本。

## 5. HTTP 接口契约

- 路径统一 `/api/<module>/...`；平台只反代该前缀，其它 404。
- `Content-Type: application/json; charset=utf-8`。
- 写操作接受 `Idempotency-Key`；同 key 重复请求返回首次结果。
- 平台默认超时 5s；长任务 `202` + job 查询。
- 重试：`GET`/`PUT`/`DELETE` 自动一次；`POST` 需幂等键。
- 响应：UTC 时间、最小单位整数、列表 `{items, nextCursor}`、空列表 `{items: []}`。
- 分页 `cursor/limit`（默认 20、上限 200）；排序 `sort=-created_at,name`。
- 错误体 ProblemDetails；模块自定义码必须在 manifest `errorCodes` 注册。
- 健康检查：`/healthz`（不查依赖）、`/readyz`（依赖就绪，失败 503 + checks）。

平台保留错误码：`UNAUTHENTICATED`、`INSUFFICIENT_PERMISSION`、`TENANT_CONTEXT_MISSING`、`RATE_LIMITED`、`MODULE_UNAVAILABLE`、`MODULE_CONTEXT_INVALID`。

---

## 6. 权限契约

- 编码 `module:resource:action`；manifest 声明；启动对账；不一致即失败。
- **路由级**：manifest `runtime.routes` 声明路径/方法/权限点；网关最长前缀匹配，未声明默认拒绝。
- **记录级**：模块按 `X-Base-Scope` 过滤；越权资源 404、越权动作 403。
- **字段级**：平台元数据侧隐藏无权字段；模块返回数据时同样过滤；契约测试抽查。
- 平台内置应用级权限点：`<module>:view` / `<module>:config:read` / `<module>:config:write`（应用 id 作为 module 段，保持三段规则）。

---

## 7. 数据与租户

1. 每表 `tenant_id NOT NULL`，进入唯一索引与查询条件。
2. RLS 覆盖 `SELECT/INSERT/UPDATE/DELETE`；或用应用层强制 + 负向测试。
3. 跨租户访问返回 404，不泄露存在性。
4. CI 必须跑"租户 A 查租户 B"的负向用例。
5. 日志/审计/错误体不得出现其它租户标识。

## 8. 审计契约

### 8.1 事件

```json
{
  "eventId": "01J8Z...",
  "occurredAt": "2026-11-28T02:15:31Z",
  "module": "aibridge",
  "tenantId": "qingchuan",
  "actor": { "type": "user", "userId": "u_123" },
  "action": "site.update",
  "resource": { "type": "site", "id": "acme.com" },
  "result": "success",
  "errorCode": null,
  "traceId": "01J8Y...",
  "sourceIp": "10.8.2.31",
  "before": { "maxTrustLevel": "assist" },
  "after": { "maxTrustLevel": "guide" }
}
```

- `eventId` 全局唯一，是幂等键。
- `action` 用 `<resource>.<verb>`。
- `before/after` 已脱敏；敏感键沿用平台 `SENSITIVE_KEYS`。
- 禁止原始请求体、凭证、完整 PII。

### 8.2 Outbox

```sql
CREATE TABLE <module>_audit_outbox (
  event_id        text PRIMARY KEY,
  payload         jsonb NOT NULL,
  created_at      timestamptz NOT NULL DEFAULT now(),
  attempts        int NOT NULL DEFAULT 0,
  next_attempt_at timestamptz NOT NULL DEFAULT now(),
  delivered_at    timestamptz,
  last_error      text
);
CREATE INDEX ON <module>_audit_outbox (next_attempt_at) WHERE delivered_at IS NULL;
```

至少一次投递；批量 ≤100；指数退避上限 5 分钟；超过 10 次进死信并可重放。

### 8.3 Ingest

`POST /api/audit/ingest`（服务间签名 + mTLS）：

请求 `{ "events": [...] }`；响应 `{ "accepted": [], "duplicates": [], "rejected": [{ "eventId": "", "code": "" }] }`。

平台按 `tenant_id` 串行入链。

### 8.4 配置变更审计

配置写入（系统级与用户级）都必须进审计主链，但**按"一次保存 = 一个事件"聚合**，不能每个 key 一条。

```json
{
  "eventId": "01J9A...",
  "occurredAt": "2026-11-28T06:20:11Z",
  "module": "aibridge",
  "tenantId": "qingchuan",
  "actor": { "type": "user", "userId": "u_123" },
  "action": "config.update",
  "resource": { "type": "app", "id": "aibridge" },
  "result": "success",
  "traceId": "01J9B...",
  "changedKeys": ["app.aibridge.maxTrustLevel", "app.aibridge.routing.timeoutMs"],
  "before": { "app.aibridge.maxTrustLevel": "assist" },
  "after": { "app.aibridge.maxTrustLevel": "guide" },
  "revision": "43"
}
```

- 系统级：`action = config.update`，`resource.type = app`。
- 用户级：`action = user.config.update`，`resource.type = user-preference`，`resource.id = <appId>:<userId>`。
- `before/after` 只含**非敏感键**；`secretRef` 与敏感键只出现在 `changedKeys`，值不落。
- 单事件 `changedKeys` 上限 200；超过拆成多个事件，用同一 `batchId` 关联。
- 用户级事件量按租户评估；若入链吞吐成为瓶颈，允许平台在**同一租户内**做微批（仍保序）。

## 9. 配置契约与托管

### 9.1 定位：平台是唯一持久化

- 接入方**不再保留配置持久化**（不写配置文件、不建配置表、不以环境变量作为配置源）。
- 平台是配置的唯一权威存储；模块只读，且只读**合并后的有效值**。
- 模块不得提供配置写入端点；写入只发生在平台 UI / 平台管理 API。
- 例外：`secret` 类配置不存平台明文，见 §9.8。

这带来两个硬要求：

1. 模块必须实现**本地快照**（§9.6），否则平台不可用时无法重启；
2. 平台必须提供**变更历史与回滚**（§9.7），因为改错会直接影响线上。

### 9.2 分层与解析顺序

```text
descriptor.default
      ↓ 覆盖
platform 层
      ↓ 覆盖
tenant 层
      ↓ 覆盖
user 层（仅 userEditable = true 的 key）
      ↓
有效值（模块读取到的就是它）
```

- 每一层只存**覆盖项**，不存全量。
- 一个 key 是否可以出现在某一层，由 descriptor 的 `scopes` 决定。
- 用户层只能覆盖 `userEditable: true` 的 key；其它 key 即使写入也忽略并告警。

### 9.3 合并规则（必须逐条实现）

| 类型 | 规则 |
|---|---|
| 标量（string/number/boolean/enum） | 上层整键替换 |
| 对象 | **递归深合并** |
| 数组 | **整数组替换**（不做按索引合并） |
| `null` | 清除本层覆盖，回落到上一层 |
| 未知键 | 忽略 + 告警，不写入 |

- 合并结果必须可复现：同一组层值 → 同一结果。
- 模块不得自行实现合并；平台在读取接口返回**合并后的值**，同时返回来源层（§9.6）。

### 9.4 descriptor 与多语言

每个 key 必须有 descriptor：

```json
{
  "key": "app.aibridge.maxTrustLevel",
  "scopes": ["platform", "tenant", "user"],
  "userEditable": true,
  "type": "enum",
  "labelKey": "aibridge.config.maxTrustLevel.label",
  "descriptionKey": "aibridge.config.maxTrustLevel.desc",
  "default": "assist",
  "options": [
    { "value": "guide", "labelKey": "aibridge.trust.guide" },
    { "value": "assist", "labelKey": "aibridge.trust.assist" },
    { "value": "act", "labelKey": "aibridge.trust.act" }
  ],
  "group": "trust",
  "order": 10,
  "advanced": false
}
```

- **只存 i18n key，不存任何语言的文案**；枚举值也要 key。
- 翻译资源随应用注册（`i18n` 段）提供，缺失 key 时回退到 key 本身并告警。
- `scopes` / `userEditable` / `group` / `order` / `advanced` 同时决定系统页与用户页的渲染。

### 9.5 对象配置

- 用 JSON Schema 子集描述，**平铺成表单**，v1 不提供原始 JSON 编辑。
- 支持类型：`object` / `array` / `string` / `number` / `integer` / `boolean` / `enum` / `secretRef`。
- 不使用 `oneOf` / `anyOf` / `$ref` / 条件 schema；嵌套深度 ≤ 4，数组项数 ≤ 100。
- UI 扩展放在 `x-base` 命名空间（`group` / `order` / `labelKey` / `descriptionKey` / `widget` / `unit` / `advanced` / `userEditable`）。
- 数组渲染为可增删列表，每项按 `items` schema 渲染；空数组与未设置区分显示。
- 校验错误定位到叶子路径（`routing.fallback.enabled`）。
- 导入/导出由平台提供（§9.9），不走手工 JSON 编辑。

### 9.6 读取、快照与失败语义

`GET /api/config/apps/{appId}?scope=effective`（服务间签名）返回合并后的有效值：

```json
{
  "items": [
    { "key": "app.aibridge.maxTrustLevel", "value": "assist", "source": "tenant", "version": 7 }
  ],
  "revision": "42",
  "etag": "W/\"42\""
}
```

按用户读取（用户级配置）：

```http
GET /api/config/apps/{appId}/users/{userId}?tenantId=<tid>
```

```json
{
  "revision": "u:42",
  "etag": "W/\"u:42\"",
  "items": [
    { "key": "app.aibridge.maxTrustLevel", "value": "guide", "source": "user" }
  ]
}
```

- 服务间签名；应用只能读自己可见租户下的用户。
- 返回**该用户合并后**的有效值（default → platform → tenant → user）。
- `revision` 按 `(appId, tenantId, userId)` 单调递增；`If-None-Match` 返回 304。
- 单用户有效配置上限 64 KB；超过则拒绝保存并提示拆分。
- **平台侧缓存按应用配置的 TTL**（默认 120 秒，见 §9.12）；响应带 `Cache-Control: private, max-age=<ttl>` 与 `X-Base-Config-TTL`。
- 应用侧如何使用由应用自行决定；平台承诺"变更后 ≤TTL 返回新值"。

模块侧：

1. 启动时读本地快照（磁盘 JSON，含 `revision` / `etag` / 合并后全量值 / 校验和）；
2. 拉取平台；成功则**原子替换**快照并应用；
3. 拉取失败 → 用快照继续启动，并进入"配置冻结"；
4. 无快照且拉取失败 → **启动失败**（fail closed）；
5. 运行期默认 30s 轮询（`If-None-Match`），304 不做事；
6. 单键缺失 → 用 descriptor 默认值；默认值也没有 → 启动失败。

### 9.7 写入、发布与回滚

- 写入只经平台 UI / 平台管理 API，进审计（§8.4）。
- v1 采用"保存即生效"：保存成功即写新 revision，并**异步**发 `config.changed`（§9.10），不等待模块应答。
- 同时必须具备：
  - 变更历史（revision、操作者、时间、diff）；
  - 一键回滚到任意 revision；
  - 保存前 diff 预览与影响范围提示。
- 草稿/发布双阶段（approval）留到 1.1，v1 不实现。
- 每次保存产生一个新 `revision`；模块按 `revision` 单调递增应用，不回退。

### 9.8 密钥

- `secretRef` 只存引用（Vault/KMS 路径），不存明文、不回显、不写日志、不进审计值。
- 用户层不允许 `secretRef`。
- 模块启动时自行解析引用；解析失败 → 启动失败（密钥不可降级）。

### 9.9 导出与导入

- 导出：按应用导出 `platform` / `tenant` 层为 JSON，含 descriptor 版本与 revision。
- **用户层配置禁止导出**（隐私）；导出文件里不得出现 `user` 层数据，也不提供"包含用户配置"的开关。
- 导入：仅平台管理员可用；导入先校验 schema，再生成一个 revision，并进审计。
- 导出内容中的 `secretRef` 只保留引用，不解析值。
- 导入是环境迁移（staging → prod）的唯一受支持路径；不支持手工拼 JSON 直接写库。

### 9.10 变更通知（platform → module）

配置保存后**立即**向模块发事件；通知失败不影响保存，模块靠轮询收敛。

#### 端点

模块暴露 `POST /internal/events`，只在内网可达；平台**直连** `runtime.baseUrl`，不经网关，不占用 `/api/<module>/*`。

#### 事件体

```json
{
  "id": "evt_01J9C...",
  "type": "config.changed",
  "scope": "tenant",
  "occurredAt": "2026-11-28T06:20:11Z",
  "appId": "aibridge",
  "tenantId": "qingchuan",
  "revision": "t:42",
  "changedKeys": ["app.aibridge.maxTrustLevel"],
  "traceId": "01J9B..."
}
```

`scope` 为 `platform` / `tenant` / `user`：

- `platform`：`tenantId` 为 `null`，所有应用需要刷新全部租户；
- `tenant`：该租户下的所有用户配置可能受影响；
- `user`：`config.user.changed`，额外带 `userId`。

事件是**加速信号，不是正确性保证**：应用可以完全忽略事件，只靠 TTL 缓存过期也能收敛（§9.12）。
`config.user.changed` 额外带 `userId`；其它类型不带。

#### 事件类型（v1）

| type | 模块动作 |
|---|---|
| `config.changed` | 立即拉取（带 `If-None-Match`），原子替换快照 |
| `config.user.changed` | 失效该用户缓存；活跃会话刷新配置 |
| `app.disabled` | 停止对外服务（或统一返回 503），保留进程 |
| `app.enabled` | 恢复服务 |
| `key.rotated` | 重新加载密钥；旧 `kid` 保留 7 天 |
| `user.disabled` | 清理该用户的本地缓存（预留） |
| `permission.changed` | 刷新权限缓存（预留） |

未知 `type` 必须忽略并返回 2xx，不得报错。

#### 签名

复用 §4 的 HMAC 方案，签名串前缀改为 `BASE-EVENT-V1`：

```text
BASE-EVENT-V1
POST
/internal/events
<X-Base-Event-Id>
<X-Base-Event-Type>
<X-Base-Timestamp>
<X-Base-Nonce>
<lowercase hex sha256(request body)>
```

校验规则同 §4.3（±300s、nonce 去重、未知 `kid` 拒绝）。

#### 投递语义

- **至少一次**；模块按 `event.id` 去重，保留 24 小时。
- 模块返回 2xx 视为成功；4xx **不重试**（配置/实现错误，进死信）；5xx 与超时重试。
- 平台退避：1s → 2s → 4s … 上限 5 分钟，最多 10 次；超过进死信并告警。
- 投递状态在平台管理页可见（成功 / 重试中 / 死信）。

#### 多副本语义（必须写进接入方文档）

- **Webhook 不是可靠广播**：平台发到 Service/负载均衡，只有一个副本能收到。
- 因此**每个副本都必须独立轮询**（≤30s）；webhook 只是"立即拉取"的加速信号。
- 模块不得假设"收到一次事件，所有副本都更新了"。
- 需要强实时广播时，由模块内部用共享缓存/pub-sub 解决；平台不提供实例发现。

#### 时序

```text
平台保存配置
  ├─ 写库（新 revision）+ 写审计（§8.4）
  ├─ 立即返回保存结果（不等待通知）
  └─ 异步发 config.changed
        ├─ 成功：模块立即拉取并应用
        └─ 失败：重试；期间模块靠 ≤30s 轮询收敛
```

#### 仅出站模式：长轮询

模块能访问平台、但平台访问不到模块时（NAT / 防火墙），webhook 不可用。改为**模块出站调用平台**的长轮询：

```http
GET /api/apps/{appId}/events?wait=25&since=<lastEventId>
```

方向与 webhook 相反：

| 模式 | 方向 | 端点 |
|---|---|---|
| webhook | 平台 → 模块 | `POST /internal/events`（模块实现） |
| 长轮询 | 模块 → 平台 | `GET /api/apps/{appId}/events`（平台实现） |

- 有事件立即返回 200 + 事件体；无事件挂起最多 25s 后返回 204。
- 模块按 `lastEventId` 续传；断线重连从上次位置继续。
- 长轮询仍是"至多一个挂起请求"，不做多路复用；模块只需一个协程。
- 平台侧对挂起请求限流（每 app 每副本 1 条），避免连接堆积。

#### 不做

- 不做 SSE / 消息队列（v1）。长轮询已覆盖仅出站模式的实时性要求，且实现成本低。
- 不做平台调用模块执行任意动作；动作类操作走 `actions` 的网关转发。

### 9.11 契约（manifest）的注册与更新

manifest 包含 `runtime` / `permissions` / `config`（descriptor）/ `admin`。它本身也需要版本与分发，规则与配置一致：**平台是审核者，只有通过校验的版本才能激活**。

#### 三种进入方式

| 方式 | 方向 | 适用 | 默认 |
|---|---|---|---|
| **Pull** | 平台 → 模块 `GET /internal/manifest` | 双向可达（默认） | ✅ 默认 |
| **Push** | 模块 → 平台 `PUT /api/apps/{appId}/manifest` | 仅出站、平台不可入站 | 兼容 |
| **导入** | 管理员上传文件 | 迁移、审计留痕 | 可选 |

Pull 流程：

1. 平台注册应用时拉取一次；
2. 模块发布新版本后调用 `POST /api/apps/{appId}/manifest/published`（**只发信号**：`version` + `contentHash`，不带内容）；
3. 平台异步 Pull，校验后存为 `draft`；
4. 管理员在平台确认后 `activate`（默认需要确认，因为会影响导航与权限）。

Push 流程：模块直接把 bundle 推到平台，平台校验后同样进入 `draft`；仅出站模式下模块无需暴露任何入站端口。

#### bundle 格式

```json
{
  "appId": "aibridge",
  "version": "1.4.0",
  "contract": "1.0",
  "contentHash": "sha256:...",
  "manifest": { "...": "完整 manifest（含 capabilities）" },
  "publishedAt": "2026-11-28T06:00:00Z",
  "signature": "ed25519:..."
}
```

- `contentHash` 是 manifest 规范化 JSON（键排序、无空白）的 SHA-256。
- `signature` 可选；企业环境建议用发布密钥签名，平台验签后才接受。
- 同一 `contentHash` 重复提交 → 200，不产生新版本（幂等）。

#### 版本与状态

```text
draft ──activate──▶ active ──supersede──▶ deprecated
  └──reject──▶ rejected
```

- 每个应用同时只有一个 `active`。
- 激活前校验：schema、权限点对账、`admin` 引用、`runtime.routes`、descriptor 完整性。
- 校验失败 → 422 + issues 列表；`active` 版本不受影响。
- 历史版本保留，可回滚（回滚也是一次 activate，进审计）。
- 平台拒绝加载 `contract` 不在支持窗口内的版本（§11）。

#### 审计

- `app.manifest.publish`（Push/Pull 拉取成功）
- `app.manifest.activate` / `app.manifest.rollback`
- `app.manifest.reject`（校验失败，含 issues 摘要）
- 导入：`app.manifest.import`（操作者、文件哈希、来源）

#### 线下导入

`POST /api/apps/{appId}/manifest/import`，仅平台管理员：

- 接受与 bundle 相同的 JSON，或带 `SHA256SUMS` 的 tar；
- 先验哈希/签名，再校验 schema；
- 导入进入 `draft`，需显式激活；
- 导入文件与哈希归档，供审计追溯。

### 9.12 查询接口与缓存语义

**平台只定义"查询接口 + 缓存语义"，不规定应用侧怎么实现。** 应用可以每次请求都查、可以本地缓存、可以自己做批量同步——契约不关心。

#### 两个查询接口

| 接口 | 用途 | 返回 |
|---|---|---|
| `GET /api/config/apps/{appId}?scope=effective&tenantId=` | 租户级有效值（platform + tenant 合并） | 值 + revision + ETag |
| `GET /api/config/apps/{appId}/users/{userId}?tenantId=` | 用户级有效值（四层合并） | 值 + revision + ETag |

两个接口都：

- 服务间签名；只返回该应用可见租户的数据。
- 支持 `If-None-Match`，未变返回 304。
- **平台侧缓存按 TTL（默认 120 秒）**：同一 `(app, tenant, user)` 或 `(app, tenant)` 的重复查询命中缓存，不回源数据库。
- 平台侧在配置变更时**主动失效**对应缓存条目，所以正常情况是秒级生效。

#### 生效时间的两个数字

- **平台侧承诺**：变更后 **≤TTL（默认 120 秒）**，查询接口返回新值（变更时主动失效缓存，TTL 兜底）。
- **端到端**：还取决于应用侧缓存。应用若也按 120 秒 TTL，最坏 120 秒；订阅事件可做到秒级。

"TTL"（默认 2 分钟）是**平台侧接口的兜底上界**，不是端到端 SLA。应用侧怎么缓存由应用决定（§9.12 末尾仅给建议）。

#### 事件是可选加速

- 应用订阅 `config.changed` / `config.user.changed`，收到后清本地缓存，下一次查询立即拿新值。
- 不订阅也没关系，TTL 内自然收敛（默认 2 分钟）。
- 多副本、NAT、事件丢失都不影响正确性，只影响延迟。

#### 平台侧容量参考（10 万用户）

- 最坏情况：10 万用户 × 每 120 秒 1 次 ≈ **833 QPS**。
- 平台侧缓存命中后，回源数据库的只有"每用户每 TTL 一次"的第一次；实际 DB QPS 远低于此。
- 缓存内存：10 万 × 约 600 B ≈ **60 MB**，按租户分组淘汰。
- 配置变更时只失效受影响的 key（用户/租户），不整体清空。

#### TTL 是平台侧配置

TTL **不属于应用的 descriptor**，也不对租户/用户可见；它是平台的查询缓存策略，按应用可调：

| 项 | 值 |
|---|---|
| 配置键 | `platform.app.<appId>.configCacheTtlSeconds` |
| scope | `platform`（仅平台管理员可写，需 `config:platform:write`） |
| 默认值 | 120 |
| 范围 | 下限待定（上线前压测确定）～300 秒 |
| 变更审计 | `config.update`，`resource.type = app` |

变更语义：

- 保存后**清空该应用的全部配置查询缓存**（用户级 + 租户级），从下一次查询开始按新 TTL 写入。
- 不清其它应用的缓存。
- TTL 变更不影响 `revision`，也不要求应用重启。

响应头（两个查询接口都会带）：

```http
Cache-Control: private, max-age=120
X-Base-Config-TTL: 120
```

- `private`：响应含租户/用户数据，不允许共享缓存。
- `X-Base-Config-TTL` 是平台当前值，**供应用参考**；应用可以按它设置本地 TTL，也可以不设——契约不强制。
- 平台自身始终按该 TTL 缓存，与响应头一致。

#### 平台侧要求

- 缓存必须带 `(appId, tenantId, userId)` 维度，不能只按 app 缓存（会串用户）。
- 变更失效必须精确：用户级变更不清租户缓存，租户级变更不清其它租户。
- 缓存不可用时（Redis 故障）直接回源，不阻断查询。
- 管理页展示"当前缓存命中率 / 回源 QPS"，用于容量观察。

#### 应用侧（仅建议，不强制）

- 本地缓存 TTL 建议与平台下发值一致（默认 120 秒）；更短只会增加回源，不会更快。
- 有事件通道时可以做到秒级；没有就接受 1 分钟。
- 不要在每次请求里查平台——用缓存或批量同步，具体由应用自己决定。

## 12. 准入与验收

### 12.1 契约测试（按能力分组）

**通用组必跑；其余组仅在声明对应能力时跑。** 未声明的能力不测试、不判失败。

#### 通用（必跑）

1. 无签名头 → 401
2. 篡改 body → 401
3. 时间戳超 ±300s → 401
4. 重放 nonce → 401
5. 未知 `kid` → 401
6. 错误体含 `code` + `trace_id` + `params`
7. `/readyz` 在依赖断开时 503
8. manifest `contentHash` 重复提交幂等
9. manifest 校验失败 → 422，`active` 不受影响
10. manifest 回滚生效且进审计

#### `config`（声明时跑）

11. 无快照且平台不可用 → 启动失败
12. 跨租户读配置 → 404
13. 对象配置叶子校验定位到路径
14. 查询命中缓存，TTL 内不回源
15. 配置变更后平台主动失效缓存
16. 应用忽略事件时 ≤TTL 收敛
17. 租户级变更不影响其它租户缓存
18. 用户级变更不影响同租户其它用户
19. 缓存不可用时回源，不返回 5xx
20. TTL 变更清空该应用缓存，其它应用不受影响
21. 响应头带当前 TTL 且 `Cache-Control: private`

#### `events`（声明时跑）

22. `config.changed` 签名失败 → 401，不应用变更
23. 同一 `event.id` 重复投递只应用一次
24. 通知全部失败时，≤TTL 收敛
25. 未知事件类型 → 2xx 且不报错
26. 长轮询 `since` 续传不丢事件（仅出站模式）
27. `config.user.changed` 只影响该用户

#### `admin-ui`（声明时跑）

28. 未知组件降级为提示，不白屏
29. 无权字段不出现在页面与接口
30. `profile` 页只显示 `userEditable` 项

#### `audit.management` / `audit.business`（声明时跑）

31. 一次保存只产生一个事件；`changedKeys` 聚合 ≤200
32. 配置事件用 `config.update` / `user.config.update`
33. 敏感键只出现在 `changedKeys`，值不落

#### `identity` / `authorization` / `proxy.http`（声明时跑）

34. 动作越权 403、资源越权 404
35. 用户写他人配置 → 403/404

## 13. 管理面描述契约（admin）

### 13.1 定位

接入方**不写前端**。在 manifest 的 `admin` 段声明页面结构，平台用固定组件渲染：

```text
描述（manifest.admin）
   ↓ 启动校验：组件白名单 / props 类型 / 权限点存在 / proxy 路径已声明
渲染（平台 PageRenderer）
   ↓ 组件只认契约 props
数据（config 托管 / proxy 只读 / action 代理）
```

描述**不含** HTML、脚本或任意表达式。

### 13.3 组件目录（v1 只做这 5 个）

| 组件 | 用途 | 关键 props |
|---|---|---|
| `section` | 分组容器 | `title`、`description`、`collapsible` |
| `tabs` | 页内切换 | `items[]`（每个含 `id/label/sections`） |
| `form` | 配置表单 | `source`、`fields[]`、`submitLabel` |
| `table` | 列表 | `source`、`columns[]`、`rowActions[]`、`pageSize` |
| `stats` | 指标卡 | `source`、`items[]`、`refreshSeconds` |
| `actions` | 动作按钮组 | `items[]`（`label`、`method`、`path`、`confirm`、`permission`） |

**不在 v1**：图表、看板、画布、富文本、条件显示、字段联动。需要这些 → 用 iframe 或平台定制页。

### 13.4 字段与对象

#### 标量

`text` / `textarea` / `number` / `integer` / `boolean` / `select` / `date` / `datetime` / `stringList` / `secretRef`。

- `secretRef` 只显示"已配置/未配置"，不回显值；用户层禁用。
- `stringList` 按行或可增删标签编辑，空列表与未设置要区分。
- `select` 的选项必须有 i18n key（§9.4）。

#### 对象：schema 子集 + 平铺

```json
{
  "key": "app.aibridge.routing",
  "type": "object",
  "schema": {
    "type": "object",
    "properties": {
      "timeoutMs": { "type": "integer", "minimum": 100, "maximum": 30000,
                     "x-base": { "unit": "ms", "order": 10 } },
      "retries":   { "type": "integer", "minimum": 0, "maximum": 5 },
      "fallback":  { "type": "object", "properties": {
                       "enabled": { "type": "boolean" },
                       "path":    { "type": "string", "maxLength": 200 }
                     } }
    },
    "required": ["timeoutMs"]
  },
  "x-base": { "group": "routing", "labelKey": "aibridge.config.routing.label" }
}
```

- 支持：`object` / `array` / `string` / `number` / `integer` / `boolean` / `enum` / `secretRef`。
- **不支持**：`oneOf` / `anyOf` / `allOf` / `$ref` / 条件 schema / 自定义校验脚本。
- 嵌套深度 ≤ 4；数组项数 ≤ 100；对象属性数 ≤ 100。
- `x-base` 扩展：`group` / `order` / `labelKey` / `descriptionKey` / `widget` / `unit` / `advanced` / `userEditable` / `placeholderKey`。
- 数组渲染为可增删列表，每项按 `items` 渲染；支持上移/下移，不支持拖拽排序。
- 校验错误定位到叶子路径；提交前做一次全量校验。
- **v1 不提供原始 JSON 编辑**；导入/导出走 §9.9。

#### 通用属性

- `scopes`：该字段允许出现在哪些层（`platform`/`tenant`/`user`）。
- `userEditable`：是否允许出现在 `profile` 页。
- `group` / `order`：系统页与用户页共用的分组与排序。
- `advanced`：默认折叠到"高级"区域。

### 13.5 数据源

| 类型 | 语义 | 写操作 | 可用 placement |
|---|---|---|---|
| `config` | 平台托管配置，`scope` 决定层 | 平台保存，进审计 | app / profile |
| `proxy` | 转发到模块只读端点 | 不允许 | app |
| `action` | 单次写操作 | 网关转发 + 权限 + 审计 | app |

- `config` 必须声明 `scope`；`profile` 页只能使用 `scope: "user"`。
- `proxy` / `action` 的路径必须已在 `runtime.routes` 声明。
- `proxy` 的权限点必须是 `:read`；写操作不允许走 `proxy`。

### 13.6 校验与降级

启动时校验，失败 **fail-fast**：

1. 组件在白名单；
2. props 类型正确、必填项齐全；
3. `permission` 已在 manifest 注册；
4. `proxy` 路径在 `runtime.routes` 中声明；
5. `form.fields[].key` 在 config 声明中存在；
6. 页面 `id` 唯一。

运行期降级：

- 未知组件 → 渲染"该组件需要升级平台"，**不白屏**；
- 未知字段类型 → 当文本展示 + 一条控制台告警；
- proxy 失败 → 该区块显示错误 + 重试，不影响其它区块。

### 13.7 安全

- 描述文件按不可信输入处理：白名单组件、禁止 HTML、禁止表达式；
- 所有写操作走网关权限判定，不信任描述里声明的权限（描述只用于 UI 展示）；
- `confirm` 文案由平台渲染，不接受 HTML；
- 描述大小上限 256 KB，页面数上限 50。

### 13.8 系统页与用户页的差异

| 维度 | 系统页（`app`） | 用户页（`profile`） |
|---|---|---|
| 位置 | 应用管理页内 | 个人中心，按应用分组 |
| 权限 | `<module>:config:read/write` | 本人（无需额外权限点） |
| 可写 scope | platform / tenant | user |
| 可见字段 | 全部（含 secret、advanced） | 仅 `userEditable`，secret 不出现 |
| 覆盖状态 | 显示"来自平台/租户/默认" | 显示"继承自租户/平台" + 重置 |
| 审计 | `config.update` | `user.config.update`（批量事件） |
| 保存粒度 | 一个页面一次 revision | 一个页面一次 revision |

用户页的交互要求：

- 每项显示有效值、来源层、"重置为继承值"；
- 保存前 diff 预览（受影响 key 列表），保存后一个批量审计事件；
- 用户只能写自己的 `userId`；管理员对用户配置默认只读，不提供代写开关；
- 应用被停用或用户失去应用可见性时，对应分组隐藏，但数据保留。

个人中心的分组规则：

- 只显示"该用户可见 + 至少有一个 `userEditable` 项"的应用；
- 按应用名排序，应用内按 `group` / `order`；
- 不显示系统级配置入口，避免用户误改平台值。

## 17. 网络前提、可达性与协议选择

### 17.1 前提

**平台在公网，应用必须能访问平台；访问不了平台的应用不在支持范围。**

这条前提删掉了大量复杂度：不考虑气隙网络、不考虑平台反向穿透 NAT、不做离线包同步。

剩下的唯一变量是**应用是否有公网入站**：

- **A 双向可达**（默认）：平台能访问应用的 `/api/<module>/*` 与 `/internal/events`。
- **B 仅出站**（兼容）：应用能访问平台，但平台访问不到应用（NAT/防火墙）。
- **C 不可达**：不支持。

### 17.2 可达性与能力

| 能力 | 双向可达 | 仅出站 |
|---|---|---|
| `config` 托管 | ✅ | ✅ |
| `events` 通知 | ✅ webhook（平台→模块） | ✅ 长轮询（模块→平台） |
| `admin-ui` | ✅（数据来自 config） | ✅ |
| `audit.management` | ✅ 出站 ingest | ✅ 出站 ingest |
| `identity` / `authorization` | ✅ | ⚠️ 可校验，但无法反代业务请求 |
| `proxy.http` | ✅ 网关反代 | ❌ 平台不可入站 |
| `observability` | ✅ 平台拉取 | ⚠️ 应用上报 |
| `manifest` 注册 | ✅ Pull | ✅ Push |

首批接入不声明 `proxy.http` / `identity`，因此"仅出站"没有阻塞项。

### 17.3 协议选择

#### 不做自定义 TCP

- 需要自己做分帧、心跳、重连、TLS、代理兼容、可观测性；
- 公网环境里 HTTP(S) 是最容易被防火墙、WAF、CDN 接受的协议；
- 真需要双向流（实时日志、流式 token），用 **WebSocket over TLS** 或 SSE，而不是裸 TCP；
- v1 的事件频率是"配置变更、密钥轮换"级别，HTTP 长轮询完全够。

#### 不对应用暴露 Kafka

- 配置变更事件是**低频、小消息、要最新状态**；Kafka 的优势是高吞吐、持久化日志、多消费者，这里用不上；
- 引入 Kafka 意味着平台运维集群、应用引入客户端库、公网暴露要加 SASL/TLS，接入成本陡增；
- "最新状态"用 `revision + 拉取` 比 offset 语义更简单，也不会因为消费滞后而应用旧配置；
- 平台**内部**如果将来需要事件总线（审计、通知、工作流），可以用 outbox + 队列，但对应用仍只暴露 HTTP。

### 17.4 公网安全基线

平台 → 应用（A 模式）：

- **mTLS 优先**；不具备时用 §4 的 HMAC + IP 白名单；
- webhook 端点只暴露 `/internal/events`，不暴露管理面；
- 平台侧对每个应用限流，防止一个应用的慢响应拖垮通知队列。

应用 → 平台：

- 强制 TLS；服务令牌（client credentials），支持轮换与吊销；
- 令牌只用于服务间调用，不得复用用户 JWT；
- 平台按应用与租户双维度限流。

平台入口：

- WAF + 速率限制 + 租户配额；公网暴露的 `/api/*` 与 `/internal/*` 分开限流；
- 失败认证、重放、异常签名计入安全指标并告警。

### 17.5 拓扑声明

接入方在 manifest 的 `runtime` 中声明：

```json
{
  "reachability": "bidirectional",
  "eventDelivery": "webhook",
  "businessPath": "gateway"
}
```

- `reachability`: `bidirectional` / `outbound-only`
- `eventDelivery`: `webhook` / `long-poll`
- `businessPath`: `gateway` / `command-queue` / `none`

平台启动时按声明选择实现；声明与实测不符 → 降级并告警（例如声明 webhook 但连续失败，自动切到长轮询）。

## 18. 开放问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 模块是否允许独立域名 | Cookie/CORS/嵌入 | 默认同源 |
| 2 | 权限摘要下发 vs 回调 | 性能 vs 灵活性 | 路由级网关判定；额外走 evaluate |
| 3 | 审计保序范围 | 链校验复杂度 | 按租户串行 |
| 4 | 是否提供草稿 → 发布双阶段 | 误改风险 vs 复杂度 | v1 不做；先做历史 + 回滚 |
| 5 | 用户级审计的量级上限 | 入链吞吐 | 微批 + 单事件 200 key 上限；上线前压测 |
| 6 | 对象平铺的表达力上限 | 复杂配置能否表达 | 深度 4 / 属性 100 / 不支持 oneOf；超出走应用定制页 |
| 7 | 复杂页面是否接受 iframe | 范围控制 | 接受，作为 20% 的兜底 |
| 8 | 是否需要 SSE / MQ 做实时广播 | 多副本一致性 | v1 不做；长轮询已覆盖仅出站 |
| 9 | 仅出站模式是否需要动作类 | 命令队列是否要做 | v1 不做；首批只做配置 + 只读快照 |
| 10 | 公网双向可达时是否强制 mTLS | 接入门槛 vs 安全 | 推荐 mTLS，HMAC + IP 白名单作为降级 |
| 11 | 配置缓存 TTL 的下限 | 回源压力 | 默认 120s、上限 300s；下限待上线压测后确定 |

## 需求描述

交付可被业务方按需引入的前端基础包，覆盖 **API client、登录态与权限判定、主题令牌、基础 UI 组件、通用 hooks**。

本需求是 REQ-001「通用项目底座」的拆分子项，负责其中的一个能力域。

**本期为「核心三包 + 权限闭环」**：交付能真实跑通的最小闭环 —— 类型安全 API client、token 自动刷新、
`can()` 权限判定、路由守卫、主题令牌。**Storybook 与 OpenAPI 类型生成延后**（见「不在范围内」）。

## 交付边界（本轮）

### 范围内

1. **`GET /api/rbac/me/permissions`** —— 后端补齐「当前用户实际拥有的权限点」的读取出口
   （当前**不存在**任何这样的接口，登录响应的 `permissions` 恒为空数组）。
2. **登录响应填入 `permissions`** —— `LoginResponse.permissions` 由「恒空」改为真实权限点集合。
3. **`@base/sdk`** —— 类型安全 API client：统一错误处理（RFC 9457）、token 自动刷新、
   幂等键注入、租户/空间头注入。
4. **`@base/auth`** —— 登录态、当前用户、`can()` 判定、路由守卫、`<Can>` 组件。
5. **`@base/theme`** —— 设计令牌、暗色模式、品牌主色接入。
6. **`@base/ui`** —— 基础组件（按钮、输入、卡片、表格、对话框）与 token 消费。
7. **`@base/hooks`** —— 分页、表格状态、SSE/WebSocket、剪贴板。

### 不在范围内

- **Storybook** —— 依赖树重，本机磁盘预算 20G（已用 ~4G）；延后到 REQ-012 之后统一评估。
- **OpenAPI → 类型生成** —— 需要后端先产出 OpenAPI 产物（当前后端**没有** `utoipa` 依赖，
  加它会突破 `Cargo.lock` 依赖预算基线，见 D22）；延后到后端有 OpenAPI 产物时再做。
- **`@base/i18n` 的多语言** —— 完整 i18n 属 REQ-021；本期只保留错误码 → 文案的映射能力。
- **`@base/schema` 的元数据驱动渲染器** —— 属 REQ-012。

## 功能要求

- **后端**：`GET /api/rbac/me/permissions` 返回当前用户在该租户下的有效权限点集合（展开通配）。
- **SDK**：请求/响应类型与后端一致；错误体按 RFC 9457 解析为稳定的错误码（不暴露后端英文原文）；
  access token 过期时自动刷新并重放原请求（并发请求只刷新一次）；写操作自动注入 `idempotency-key`。
- **Auth**：`can(permission)` 基于后端下发的权限点集合在**前端本地判定**；`<Can>` 组件按权限点
  显隐；路由守卫在无权限时跳 403。
- **Theme**：设计令牌以 CSS 变量输出；暗色模式可切换；主色来自 REQ-010 的品牌接口（不硬编码）。
- **UI**：基础组件消费 theme 令牌，不硬编码颜色。
- **Hooks**：分页、表格状态、SSE/WebSocket、剪贴板。

## 需求描述

让底座从第一天起就是多语言 / 多时区 / 多币种的，而不是事后改造 —— **事后补国际化是最贵的返工**。

本需求是 REQ-001「通用项目底座」的拆分子项，负责其中的一个能力域。

## 依赖

- REQ-006（多租户 —— 语言/时区/币种是租户级配置）
- REQ-010（配置 —— 承载租户级偏好）
- REQ-011（前端 SDK —— `@base/i18n` 与渲染器）
- REQ-012（元数据渲染 —— 字段 label 也需要本地化）

## 交付边界（本轮，经用户拍板）

### 范围内

1. **后端零翻译** —— 错误体**不含**面向用户的中文，只返回 `code` + `params`
2. **语言协商** —— **用户显式偏好 > `Accept-Language` > 租户配置 > 平台默认**
   > ⚠️ **起草时我写反了**（原本写「Accept-Language > 用户偏好」）。
   > 想清楚后：**用户在我们系统里显式设的偏好最权威** ——
   > 他设了 English 就该看英文，不管浏览器语言是什么。
   > `Accept-Language` 只是「用户没设时的最佳猜测」。见 design §3.1。
3. **翻译键体系** —— 键的命名规则 + 单一来源
4. **缺失键回退** —— 回退基准语言 + **记录**，不出现空白、不泄露 key 原文
5. **租户级偏好** —— 语言 / 时区 / 币种走 REQ-010 的 config（`scope: tenant`）
6. **时区** —— 时间存 UTC（已有），按用户/租户时区**渲染**；同一时间点在不同时区正确
7. **币种（工具 + 汇率表）** —— `Money` 类型（**整数最小单位，零浮点**）+
   格式化 + **汇率快照表** + 整数换算
8. **前端 `@base/i18n`** —— 翻译加载 / 切换 / 回退，CSR 与 SSR 一致

### 不在范围内（**明确延后**）

- **通知模板 / 邮件 / 导出文件的国际化** —— 依赖 **REQ-015（通知）** 与
  **REQ-018（导出）**，两者**均未开工**。本轮做会定义一套注定返工的形状。
  > **用户拍板（2026-11-19 19:00）**：明确延后，不在本轮做假接口。
- **业务模块自身的领域术语翻译** —— 业务模块自行维护，但接入同一键体系
- **后端渲染本地化文案**（邮件正文、PDF 报告）—— 与上一条同因
- **第三方翻译服务接入**（DeepL 等）—— 键体系稳定后再议

## 功能要求

### 后端

- **错误体零中文**：`title` 改为英文；`detail` 本就是英文 ASCII（已有）
- `Accept-Language` 解析与协商（BCP 47，支持 `zh-CN`, `en-US`, `zh-CN;q=0.9`）
- 租户级 `locale` / `timezone` / `currency` 通过 config 声明（`scope: tenant`）
- **`Money` 类型**：`{ minorUnits: i64, currency }`，**不做浮点运算**
- **汇率快照**：`platform_fx_rate` 表（`from` / `to` / `rateMicros` / `asOf` / `source`）
- 跨币种换算**必须带快照引用**（可追溯「用的是哪一天的汇率」）

### 前端

- `@base/i18n`：翻译资源加载、语言切换、缺失键回退（+ 记录）
- 按 locale 格式化日期 / 数字 / 货币（**用 `Intl`**，不自造）
- 时区渲染：同一 UTC 时间点按用户/租户时区显示
- 语言偏好：用户级（切换即生效，持久化）

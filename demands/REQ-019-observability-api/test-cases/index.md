## 覆盖核对

- 9 条 AC **全部**有用例；**无 AC 无用例**。
- 验收标准里的**每条判据**（含 ⚠️ 标注的子判据）都有对应用例：
  - 正向判据 → 「应通过」类用例
  - 阴性对照（如 AC-S-036 步骤 2「未弃用端点不带头」）→ 单独的对照用例
  - 阳性对照（如 AC-S-035 步骤 2/5「改产物/改代码后 --check 必须红」）→ 单独的变异用例

## 必须有的「对照类」用例（防止假绿）

这几条**不是**功能验证，而是**证明判据有区分力**的对照，缺了就是假绿：

| 用例 | 对照什么 | 为什么必须有 |
|---|---|---|
| TC-019-041 | `?page=1&page_size=10` 仍可用 | 证明「统一契约」没破坏已验收的分页方式 |
| TC-019-048 | 改 `openapi.json` 的 `info.title` → `--check` 非 0 | 证明 `--check` 真在比对（不是恒返回 0） |
| TC-019-049 | 改一个 DTO 字段名 → `--check` 非 0 且有**差异行** | 证明「代码变了产物没更新」会被抓住 |
| TC-019-054 | 未弃用端点**不**带 `Deprecation`/`Sunset` | 证明不是「给所有响应都加头」 |
| TC-019-062 | `OTEL_SDK_DISABLED=true` 时 `is_enabled() == false` | 证明开关真生效 |
| TC-019-066 | **关闭限流时**，限流表坏了也不影响就绪 | 证明就绪检查是**条件性**的，不是无条件 |

## 判定口径（§9.15）

每个用例的「判据」字段必须写成：
`<断言内容> @ <file:line> <函数名>`

⚠️ 不许写「测试通过」「行为符合预期」这类无法核对的话。
用例实现后要把**真实行号**回填（现在是规格阶段的预设，实现后校准）。

# 需求：元数据驱动渲染

- **需求编号**: REQ-012
- **父需求**: [REQ-001 通用项目底座](../REQ-001-platform-foundation/demand.md)
- **优先级**: P0
- **状态**: 已就绪（2026-11-19 15:10 规格写实）
- **所属迭代**: Sprint 4
- **更新时间**: 2026-11-19 15:10

## 需求描述

用**后端元数据**描述实体，前端**通用渲染器**渲染，实现零前端代码的标准 CRUD 页面。

本需求是 REQ-001「通用项目底座」的拆分子项，负责其中的一个能力域。

**这是底座可用性的第一块试金石**：如果 REQ-011 交付的前端 SDK 真的好用，
那么「新增一个列表/表单页面」应该**只写元数据、不写前端代码**。

## 依赖

- REQ-002（工程基线）
- REQ-009（RBAC —— 提供权限判定与 `PermissionChecker`）
- REQ-011（前端 SDK —— 提供 `@base/sdk` / `@base/ui` / `<Can>` / 路由）

## 交付边界（本轮，经用户拍板）

### 范围内（第一棒）

1. **`manifest.json` 新增 `schema` 段** —— 业务模块声明实体与字段元数据
2. **元数据读取接口** —— `GET /api/schema/<moduleId>/<entityKey>`
3. **元数据按权限过滤** —— 无权字段**连元数据都不返回**（不泄露「有个字段叫 salary」）
4. **字段级权限：平台唯一序列化入口** —— 数据响应用它输出，无权字段**不出现在响应里**
5. **契约 C-6** —— 扫描「声明了字段权限却没走序列化器」的违规
6. **前端通用渲染器** —— `SchemaTable`（列表 + 分页）/ `SchemaForm`（表单 + 校验）
7. **零代码 CRUD 闭环** —— 新增同类页面**只写元数据，不写前端代码**

### 不在范围内

- **CRUD 代码脚手架**（`cargo xtask` 生成后端 CRUD）—— 用户拍板**延后**。
  理由：元数据形状没被真实跑通前就固化脚手架，返工风险最高。
- **通用数据接口**（平台按元数据自动读写任意表）—— 与 ADR A7「模块自包含、不共享表」冲突。
  数据访问仍由业务模块的 `Repository` 承担。
- **元数据管理界面**（在 UI 里改元数据）—— 元数据是**编译期声明**（ADR A5），不是运行时数据。
- **复杂布局**（多列栅格、分组折叠、条件显隐的复杂表达式）—— 业务模块自行实现。
- **导出 / 导入 / 批量操作** —— 见 REQ-018。

## 功能要求

### 后端

- `manifest.json` 的 `schema` 段：实体 → 字段列表（`key` / `label` / `type` /
  `required` / `permission` / 校验参数）
- 启动时**校验** schema 段（非法 → 进程起不来，与 config 段同款 fail-fast）
- `GET /api/schema/<moduleId>/<entityKey>` 返回**已按当前用户权限过滤后**的元数据
- 字段级权限的唯一序列化入口：业务模块用它输出数据，无权字段被剔除
- 契约 C-6 扫描违规（声明了字段权限但没用序列化器）

### 前端

- `@base/schema`：实体/字段类型、字段可见性判定、表单校验、列表查询构造
- `apps/shell` 的 `SchemaTable` / `SchemaForm`（组件落应用侧，同 REQ-011 裁定 #7）
- 列表：分页（游标）、排序、过滤、空态
- 表单：按 `required` / 类型校验、错误定位到字段
- 增删改查闭环：列表 → 新建/编辑表单 → 提交 → 刷新列表

- 标准 CRUD **零前端代码**可交付（新增同类页面只加 meta）

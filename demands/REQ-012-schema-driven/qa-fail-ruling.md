## 1. HIGH（全修）

### H-1：自带夹具不授 `sandbox:demo:*` → 6 条 E2E 全 skip、exit 0

**根因**：`scripts/seed-e2e.sh:162-164` 只授 `rbac:role:read/write`；
REQ-012 新加了 `sandbox:demo:read` / `sandbox:demo:write`，播种脚本没跟上。

**裁定**：**修两处**（缺一不可）：

**① 播种脚本补授权**
```sql
-- e2e-role-read  + sandbox:demo:read
-- e2e-role-write + sandbox:demo:read, sandbox:demo:write
```
**② E2E 把「403」从 `skip` 改成 `fail`**

这是**更重要的那条**。现在的写法：
```ts
test.skip(status !== 200, `夹具不可读 ...（HTTP ${status}）`);
```
→ 403 被当成「环境没准备好」而**静默跳过**。

**但 403 的含义是「夹具授权不对」，那是必须暴露的配置缺陷**，不是环境前置。

**新规则**（写进 E2E spec 的注释与所有 skip 判据）：
| 情形 | 处置 | 理由 |
|---|---|---|
| 元数据 404（后端未声明实体） | **skip** | 这是"另一个 Dev 还没做完"的前置 |
| 列表 **403** | **fail** | 夹具授权缺失 = 配置 bug，必须红 |
| 列表 500 | **fail** | 服务端错误 |
| 网络不可达 | **skip** | 环境没起 |

**新增决策 D108**：**E2E 的 skip 只允许用于「被测系统尚未就绪」，「夹具/授权不对」必须 fail**。

### H-2：空态用例 vs 零代码用例数据前置互斥

**根因**：
- 空态用例（`:143`）要求 `demoNote` 表**为空**
- 零代码用例（`:199`）要求 `demoNote` 有**数据**

两条用例**互相踩数据** → 必然一条红。

**裁定**：**用例自己管理数据前置**（测试独立原则）。

| 用例 | 前置动作 |
|---|---|
| 空态用例 | **先清空** `demoNote`（`DELETE` 全部）→ 验空态 |
| 零代码用例 | **先创建**一条 `demoNote` → 验渲染；结束后清理 |
| CRUD 用例 | 用**自己创建**的记录（`title` 带唯一后缀），不依赖既有数据 |

**每条用例必须能在任意顺序、任意初始状态下独立通过。** 这是 E2E 的基本功。

### M-1：`AGENTS.md` 没写「装配层例外」，且与 `deps.rs` **直接矛盾**

**问题**：
- `deviation-ruling §1.6` 我要求把「装配层例外」写进 `AGENTS.md` —— **没落**

**这是我最反感的那类问题**：**文档与代码不一致**。
按我自己的话（Sprint 3 教训 3）：「注释与代码不一致比没有注释更坏」——

**裁定**：**修**。`AGENTS.md` 要写清：

|---|---|
| `platform-core` / `platform-db` / `platform-iam` / `platform-org` / `platform-rbac` / `platform-schema` | ❌ 不能 |
| **`platform-server`** | ✅ **可以**（唯一例外，`ASSEMBLY_CRATES` 白名单） |

**并且**：`AGENTS.md` 的那句「一旦反向依赖业务模块即失败」要改成

### L-6 的 AC 修订

原 AC-S-083 步骤 5：「`number` 字段填非数字后提交 → 不发出请求」。

**问题是真浏览器里 `input[type=number]` 根本不接受 `abc`** ——
输入非数字字符时 `value` 为空串，所以「填非数字」这个前置**物理上不可达**。

**改为**：
- 步骤 5 → 「`number` 字段填**超出 `min`/`max` 的值**（如声明 `min:0` 时填 `-1`）→ 不发出请求，
  错误定位在 `number` 字段」
- 并加一条：「`number` 字段留空且 `required` → 同 `required` 规则」

**这不是实现缺陷，是 AC 内部矛盾** —— 我在 rev 2 里没考虑浏览器的原生控件行为。

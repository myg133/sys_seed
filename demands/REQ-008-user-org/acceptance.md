## 本需求自有 AC

### AC-S-011: 组织树操作
- **前置条件**: 已有 company → dept → team 三层组织与若干成员
- **测试步骤**: 1. 调整部门归属（移动节点） 2. 批量移动用户 3. 查子树成员 4. 查 `path_labels`
- **预期结果**: 移动后子树查询**立即反映新结构**；
  `path_labels` 与 `parent_id` **保持一致**（不一致时以 `parent_id` 为准并可重建）；
  用户的成员关系**不被移动操作破坏**
- **类型**: 功能

### AC-S-012: 同步幂等
- **前置条件**: 一个 SCIM 目标服务（测试用 mock）
- **测试步骤**: 1. 连续执行两次全量同步 2. 查目标服务的条目数
- **预期结果**: **不产生重复条目**；第二次同步是幂等更新（PUT 语义）
- **类型**: 功能

### AC-S-013: SCIM 出站字段映射正确
- **前置条件**: 配置了 provider 的字段映射（用户名 / 邮箱 / 显示名 来自不同属性）
- **测试步骤**: 1. 在底座改一个用户的显示名 2. 触发推送 3. 查目标服务
- **预期结果**: 目标服务收到**按映射规则转换后**的值；推送失败进入重试且不阻塞本地请求
- **类型**: 功能

### AC-S-014: 冲突进人工队列且是字段级
- **前置条件**: 同一用户在底座与外部系统有不同的**某一个字段**的值；冲突策略为 `manual`
- **测试步骤**: 1. 执行全量对账 2. 查冲突队列 3. 人工裁决 4. 再同步
- **预期结果**: 冲突**记录到字段级**（`field` / `local_value` / `remote_value`），
  不是整条记录；裁决后按裁决结果生效；**不静默覆盖任何一侧**
- **类型**: 功能 / 安全

### AC-S-015: 离职自动禁用并撤销会话
- **前置条件**: 外部源把某用户标记为离职（AD 的 `userAccountControl` 位 / SCIM `active:false`）
- **测试步骤**: 1. 同步 2. 查用户状态 3. **用该用户之前拿到的 refresh token 刷新** 4. 查角色绑定
- **预期结果**: 账号被禁用；**旧的 refresh token 立即失效**（不只是等 access TTL 到期）；
  角色与组织成员关系已解绑；产生审计事件
- **类型**: 安全

### AC-S-016: AD 离职位运算识别正确
- **前置条件**: AD 中 `userAccountControl` 的不同取值组合
- **测试步骤**: 1. 构造启用 / 禁用 / 锁定等取值 2. 同步 3. 查判定结果
- **预期结果**: 按**位运算**判定，不是简单布尔比较；不同取值的判定全部正确
- **类型**: 功能 / 安全

### AC-S-017: 组织变更事件通知受影响人
- **前置条件**: 已实现 `NotificationSender` 扩展点
- **测试步骤**: 1. 把用户移出某节点 2. 移动某节点 3. 查发出的通知
- **预期结果**: 受影响用户与相关节点成员收到通知；**节点删除前成员已被处理**
  （不留悬空成员关系）
- **类型**: 功能

### AC-S-018: 组织数据带租户维度
- **前置条件**: 两个租户各有同名组织节点
- **测试步骤**: 1. 以 tenant_a 的上下文查子树 2. 用 tenant_b 的 id 在 tenant_a 下查
- **预期结果**: 只返回 tenant_a 的节点；跨租户 id 访问被拒；组织表按 REQ-006 的
  `tenantScoped` 声明生成 RLS policy
- **类型**: 安全

### AC-S-019: 结构可供 REQ-009 消费
- **前置条件**: 组织数据已就绪
- **测试步骤**: 1. 查「本部门及下级」判定所需的结构 2. 查「我的下属」判定所需的结构
- **预期结果**: `org_node` / `user_org` / `user_position` / 汇报关系**足以支撑 REQ-009 的数据范围判定**，
  且 REQ-008 **不实现任何权限判定逻辑**（判定在 REQ-009）
- **类型**: 功能 / 可维护性

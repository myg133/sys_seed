## 本需求自有 AC

### AC-S-009: 密码策略可配置
- **前置条件**: 密码策略可按租户配置（最小长度、复杂度、有效期、历史不重复）
- **测试步骤**: 1. 用不满足策略的密码注册 / 改密 2. 用满足策略的密码 3. 查历史重复
- **预期结果**: 不满足时拒绝并指出**具体违反哪条规则**（`PASSWORD_POLICY_VIOLATION` + `params`）；
  满足时可成功；与最近 5 次重复的密码被拒（`PASSWORD_REUSED`）
- **类型**: 功能 / 安全

### AC-S-010: 密钥轮换不中断
- **前置条件**: JWT 签名密钥从环境注入，带 `kid`
- **测试步骤**: 1. 用密钥 K1 签发令牌并验签 2. 轮换到 K2 3. 用 K2 签发并验签 4. 查 JWKS 端点
- **预期结果**: 轮换后新令牌用 K2 签发可验签；**宽限期内旧令牌（K1）仍可用**；
  JWKS 同时暴露两个公钥；私钥**绝不出现在** JWKS 响应里
- **类型**: 安全

### AC-S-011: 密码哈希不可逆且参数可配
- **前置条件**: 密码以 Argon2id 哈希存储
- **测试步骤**: 1. 查用户表存储值 2. 用不同参数哈希同一密码比对 3. 确认格式是 PHC 标准串
- **预期结果**: 存储值**不含明文**，是 `$argon2id$...` 形式的 PHC 串（算法自描述），
  换算法或调参数不必改表结构；参数可按目标机器配置
- **类型**: 安全

### AC-S-012: 登录失败不泄露账号是否存在
- **前置条件**: 准备「存在的账号 + 错密码」与「不存在的账号」两种输入
- **测试步骤**: 1. 两种输入各登录一次 2. 比对响应体、状态码、错误码 3. 比对响应耗时
- **预期结果**: 两种情况的**响应体与错误码完全相同**（`INVALID_CREDENTIALS`）；
  耗时**接近**（账号不存在时也要执行一次假哈希校验），不构成时序枚举
- **类型**: 安全

### AC-S-013: 密码重置不泄露邮箱是否存在
- **前置条件**: 一个已注册邮箱 + 一个未注册邮箱
- **测试步骤**: 两者都调 `POST /api/iam/password/forgot`
- **预期结果**: 两次响应**完全相同**（成功语义），不通过响应差异泄露注册状态
- **类型**: 安全

### AC-S-014: refresh token 轮换与重放检测
- **前置条件**: 已登录，持有 refresh_1（属于 family F）
- **测试步骤**: 1. 用 refresh_1 刷新 → 拿到 refresh_2 2. **再次**使用 refresh_1 3. 用 refresh_2 刷新
- **预期结果**:
  1. refresh_1 **立即失效**（旧 token 不能重复用）
  2. 第二次用 refresh_1 → 判定为泄露 → **整个 family F 全部作废**，返回 `TOKEN_REUSE_DETECTED`
  3. refresh_2 也**已失效**（family 被作废）
- **类型**: 安全

### AC-S-015: TOTP 防重放与恢复码一次性
- **前置条件**: 已绑定 TOTP
- **测试步骤**: 1. 用某验证码登录成功 2. **立刻用同一个验证码**再登一次 3. 用恢复码登录 4. 再用同一恢复码
- **预期结果**: 第 2 步被拒（同一时间步的验证码不可复用）；恢复码**只能用一次**，用过的报无效
- **类型**: 安全

### AC-S-016: 会话带租户维度且不可跨租户复用
- **前置条件**: 用户在 tenant_a 有有效会话；token 绑定 tenant_a
- **测试步骤**: 1. 用 tenant_a 的 access token 请求 tenant_b 的接口 2. 查会话记录的 tenant_id
- **预期结果**: 跨租户访问被拒（404/403）；**所有会话记录都带 tenant_id**
- **类型**: 安全

### AC-S-017: 登录限流与账号锁定
- **前置条件**: 限流与锁定阈值可配
- **测试步骤**: 1. 同一账号连续失败达阈值 2. 继续尝试 3. 锁定期过后再试 4. 成功登录后计数清零
- **预期结果**: 达阈值后锁定并返回 `ACCOUNT_LOCKED`；锁定期内即使密码正确也拒；
  锁定期过后可再试；成功登录后失败计数清零
- **类型**: 安全

### AC-S-018: 设备会话可管理
- **前置条件**: 同一账号在两台设备登录
- **测试步骤**: 1. 列出会话 2. 从 A 端下线 B 3. 登出全端
- **预期结果**: 会话列表展示设备 / IP / 最近活跃；从 A 下线 B 后 **B 的 refresh token 立即失效**；
  「登出全端」作废该用户全部 family
- **类型**: 功能 / 安全

### AC-S-019: 错误体符合契约 C6
- **前置条件**: 触发若干错误路径
- **测试步骤**: 逐个检查错误响应的 `detail` 字段
- **预期结果**: `detail` **必须是英文 ASCII**（面向开发者）；
  面向用户的中文文案由前端 i18n 按 `code` 渲染，后端**不得**拼中文句子。
  ⚠️ REQ-005 刚踩过这个坑 —— 本条要重点守
- **类型**: 功能 / 可维护性

### AC-S-020: 依赖预算与编译资源在可控范围
- **前置条件**: 本机 7.7G 内存 / 4.6G 可用
- **测试步骤**: 1. `cargo tree --workspace` 数唯一 crate 数 2. 实测冷编译时间与峰值内存
- **预期结果**: 依赖树增长在**预算内**（**预算已重定基线到 235**，见下方说明）；
  冷编译峰值内存 < 1.5G；若超则 `.cargo/config.toml` 的 `jobs` 已调低；日常增量 `cargo check` < 60 秒
- **类型**: 性能
- **预算重定基线（BA 决策 2026-11-18，QA 复核后修订）**：原写「175 → 200~210」，
  实测为 **175 → 232（+57）**，超原预算 22 个 crate。**不降级依赖**，理由：
  - `jsonwebtoken` 9.x 的 `ring` 是**非可选依赖**（引入 C/汇编构建，慢且吃内存）→ 只能用 10.x 的 `rust_crypto`
  - 10.x 的 `rust_crypto` 是**全量 feature**（ed25519-dalek + hmac + p256 + p384 + rand + rsa + sha2），**无子集可选**
  - `chacha20poly1305` 对 TOTP secret 静态加密是必需的（自制密码学不可接受）
  - **实测资源全部达标**：冷 check 46.7s / 1074MB；冷 test+link 63.1s / 1414MB（< 1.5G）；增量 check 0.98s
  - 确认 `ring` / `aws-lc-rs` / `aws-lc-sys` **0 命中**（唯一含 "ring" 字样的是 `stringprep`，Unicode 库非加密库）
  → 预算基线由 210 调整为 **235**，偏差登记在追溯矩阵

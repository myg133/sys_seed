## 架构决策（ADR-0001，已采纳）

> 编号 A1~A8 对应 ADR-0001 的 D1~D8，与上方 BA 自决记录（D1~D8）是两套编号，勿混。

| # | 决策 | 采纳结论 | 生效范围 |
|---|------|----------|----------|
| A1 | 部署形态 | 模块化单体（Rust crate 树 + 前端 pnpm workspace monorepo）；模块边界从第一天划死，不共享数据库表 | 全局 |
| A2 | 多租户隔离级别 | 默认 L1 共享表 + `tenant_id` + **PostgreSQL RLS 兜底**；向上保留 L2 独立 schema / L3 独立库 | 全局（DAO / 缓存 key / 消息体 / 迁移策略） |
| A3 | 认证主体归属 | 底座自持账号 + SSO 挂载；支持「账号在底座、组织架构来自 LDAP/AD」的混合模式 | 用户模型 |
| A4 | 前端形态 | 单体 SPA + 运行时可扩展的应用路由注册表；预留微前端接口但不实现 | 前端架构 |
| A5 | 扩展点机制 | 编译期 Rust trait 插件 + 前端插槽；**能用配置表达的绝不写插件** | 扩展机制 |
| A6 | 权限引擎 | 自研表驱动 RBAC + 数据范围过滤；预留 OpenFGA / Cedar 适配层 | 权限模块 |
| A7 | 业务模块扩展模型 | 依赖方向单向 `平台 → trait ← 业务模块`；模块固定在 `modules/<name>/`，自包含 + 启停开关 | 目录结构 / 扩展点签名 |
| A8 | AI 辅助开发引导体系 | 三层引导（仓库级 AGENTS.md + 模块级 AGENTS.md + `prompts/`）+ `capabilities/` 机器可读能力索引（CI 自动生成）+ 脚手架 + CI 护栏 | 二次开发基建 |

### 采纳后的执行顺序

**扩展点骨架 + 引导体系要早于大部分业务模块开发** —— 它们是所有业务模块的适配面，晚建就意味着后面每个模块都要返工适配。

1. 认证与用户 → 2. RBAC → 3. 租户 → 4. 扩展点骨架 + 契约测试 → 5. 前端 SDK 骨架 → 6. 引导体系 → 7. SSO → 8. 工作流 / 通知 / 审计

## A. 身份与访问

### AC-001: 权限点注册表驱动前后端权限判定
- **前置条件**: 应用 manifest 声明权限点 `order:invoice:approve`；用户角色含该权限
- **测试步骤**:
  1. 前端调用 SDK `can('order:invoice:approve')`
  2. 直接 `GET /api/order/invoice/approve` 绕过 UI
- **预期结果**: 步骤 1 返回 `true` 且对应 UI 元素可见；步骤 2 返回 403
- **类型**: 功能 / 安全

### AC-002: 数据范围隔离生效
- **前置条件**: 角色 A 数据范围 = 本组织及下级，角色 B = 仅本人；两人各有测试数据
- **测试步骤**: 分别以 A、B 登录查询同一列表接口
- **预期结果**: A 看到本组织及下级全部数据，B 仅看到本人数据；数据库查询带租户与数据范围过滤条件
- **类型**: 功能 / 安全

### AC-003: 注册策略可配置且按租户隔离
- **前置条件**: 租户 T1 开启注册 + 域名白名单 `example.com`；租户 T2 关闭注册
- **测试步骤**: 用 `a@example.com` / `b@other.com` 分别在 T1、T2 尝试注册
- **预期结果**: T1 仅 `a@example.com` 通过且进入审批待定态；T2 一律拒绝注册
- **类型**: 功能

### AC-004: 邀请链接一次性且可过期
- **前置条件**: 生成有效期 1 小时、限 1 次使用的邀请链接
- **测试步骤**: 使用链接注册成功 → 再次使用同一链接；另生成一个已过期链接尝试注册
- **预期结果**: 二次使用与过期链接均被拒绝并给出明确错误码
- **类型**: 功能 / 安全

### AC-005: SSO 入站三协议
- **前置条件**: 配置 SAML IdP、OIDC IdP、LDAP 服务各一套测试环境
- **测试步骤**: 分别以三种方式登录
- **预期结果**: 均成功创建 / 关联本地账号并建立会话；协议失败时回落登录页且提示可区分
- **类型**: 功能

### AC-006: 底座作为 IdP 向第三方应用签发令牌
- **前置条件**: 注册一个第三方应用，配置授权码 + PKCE 与回调地址
- **测试步骤**: 走授权流程拿授权码 → 用 PKCE 换令牌 → 携带令牌调用应用接口
- **预期结果**: 换取到有效访问令牌；应用接口校验通过；令牌超出有效期返回 401
- **类型**: 功能 / 安全

### AC-007: 令牌轮换与撤销
- **前置条件**: 用户已登录，存在 refresh token
- **测试步骤**: 用 refresh token 换新令牌（旧 refresh 失效）→ 调用登出 → 再次用已撤销令牌
- **预期结果**: 旧 refresh token 立即不可用；登出后令牌不可用；状态码 401
- **类型**: 安全

### AC-008: 设备会话可见且可远程下线
- **前置条件**: 同一账号在两个浏览器登录
- **测试步骤**: 会话列表展示两台设备；从 A 端下线 B
- **预期结果**: B 端下一次请求被强制登出；会话列表与实际登录一致
- **类型**: 功能

## B. 组织与租户

### AC-009: 租户上下文全链路传播
- **前置条件**: 两个租户各有同名用户与同名业务数据
- **测试步骤**: 携带 `X-Tenant-Id: T1` 请求业务接口，查看返回数据、DB 查询日志、消息体
- **预期结果**: 数据仅来自 T1；DB 查询含 `tenant_id = 'T1'` 条件；发出的消息携带 T1 上下文
- **类型**: 功能 / 安全

### AC-010: 跨租户数据绝对不串
- **前置条件**: 与 AC-009 相同
- **测试步骤**: 尝试用 T1 的令牌访问 T2 的资源 ID
- **预期结果**: 返回 404 或 403（不得返回 T2 数据，也不得泄露资源存在性细节）
- **类型**: 安全

### AC-011: 组织架构 SCIM 出站同步
- **前置条件**: 目标系统实现 SCIM 2.0 `Users` / `Groups` 端点
- **测试步骤**: 在底座新增用户与部门 → 触发同步
- **预期结果**: 目标系统出现对应用户与部门条目；再次同步为幂等更新，不产生重复
- **类型**: 功能

### AC-012: 组织同步冲突进人工队列
- **前置条件**: 同一用户在底座与外部系统中的部门不同
- **测试步骤**: 执行同步
- **预期结果**: 按配置的冲突策略处理；策略为"人工待处理"时进入待处理队列并可人工裁决
- **类型**: 功能

- **前置条件**: 平台默认 `logo=A`、租户 T1 覆盖为 `logo=B`、空间 S1 再覆盖为 `logo=C`

### AC-014: 品牌配置前端实时生效

- **测试步骤**: 刷新前端页面

- **类型**: 功能

### AC-015: Feature Flag 按租户生效

- **类型**: 功能

## D. 前端底座

### AC-016: SDK 按需引入且无全局副作用
- **前置条件**: 业务前端仅引入 `@base/sdk` + `@base/auth`
- **测试步骤**: 构建生产包并检查产物依赖树
- **预期结果**: 未引入的包（图表 / 富文本 / i18n 等）不出现在产物中；无全局样式污染
- **类型**: 功能 / 性能

### AC-017: 权限组件与路由守卫联动
- **前置条件**: 用户无 `order:invoice:delete` 权限
- **测试步骤**: 打开含删除按钮的页面；直接输入该操作的 URL
- **预期结果**: 按钮不渲染；直接访问 URL 被拦截并跳转 403 页
- **类型**: 安全

### AC-018: schema 驱动零代码 CRUD
- **前置条件**: 后端提供一份列表 + 表单的元数据描述
- **测试步骤**: 前端仅用通用渲染器渲染该元数据，不写业务组件
- **预期结果**: 列表、表单、校验、分页、增删改查全部可用；新增同类页面无需新增前端代码
- **类型**: 功能

### AC-019: API 类型自动同步
- **前置条件**: 后端修改某接口响应字段
- **测试步骤**: 运行类型生成命令
- **预期结果**: SDK 类型同步更新；不匹配处编译期报错
- **类型**: 功能

## F. 平台运维与治理

### AC-022: 审计日志完整且不可篡改
- **前置条件**: 执行一次敏感操作（改权限、导出数据）
- **测试步骤**: 查询审计日志；尝试直接修改数据库中的审计记录
- **预期结果**: 日志含操作人、时间、对象、变更前后值、来源 IP；篡改后校验失败并告警
- **类型**: 安全

### AC-023: 通知多渠道投递与重试
- **前置条件**: 配置邮件与一个 Webhook 通道，Webhook 首次投递返回 500
- **测试步骤**: 触发一条通知
- **预期结果**: Webhook 按退避策略重试后成功；邮件送达；投递记录可查；用户可退订该类型
- **类型**: 功能

### AC-024: 审批流端到端
- **前置条件**: 定义一个两级审批流程（提交 → 主管 → 财务）
- **测试步骤**: 提交申请 → 主管通过 → 财务驳回 → 申请人查看
- **预期结果**: 状态按流程流转正确；驳回回到发起人并带意见；每步产生通知与审计记录；超时自动升级
- **类型**: 功能

### AC-025: 文件上传与预签名访问
- **前置条件**: 对象存储为 S3 兼容
- **测试步骤**: 上传大文件（分片）→ 获取预签名下载链接 → 下载校验
- **预期结果**: 上传成功且可断点续传；链接限时有效，过期后失效
- **类型**: 功能 / 安全

### AC-026: 导入导出异步且可回溯
- **前置条件**: 导入含 5 万行且其中 10 行数据非法
- **测试步骤**: 执行导入 → 查询任务进度
- **预期结果**: 导入异步执行，进度可查；合法行入库，非法行返回带行号与原因的回执
- **类型**: 功能

### AC-027: 限流三级生效
- **前置条件**: 租户 / 用户 / 接口三级限流分别配置
- **测试步骤**: 分别触发三种限流
- **预期结果**: 对应维度返回 429 并带 `Retry-After`；其他维度不受影响
- **类型**: 性能 / 安全

### AC-028: trace_id 全链路贯穿
- **前置条件**: 开启 OTel 采集
- **测试步骤**: 发起一次跨服务调用
- **预期结果**: 日志、链路、异步消息携带同一 `trace_id`，可完整串联
- **类型**: 功能 / 可维护性

## G. 二次开发体验与 AI 辅助开发

### AC-031: 依赖方向单向，平台不依赖业务
- **前置条件**: 存在业务模块 `order`，其 backend 实现平台定义的扩展点 trait
- **测试步骤**: 1. 只编译平台核心（排除全部业务模块）2. 检查平台核心的依赖图
- **预期结果**: 平台核心编译通过；依赖图中**不出现任何业务模块**；依赖方向恒为 平台 → trait ← 业务
- **类型**: 功能 / 可维护性

### AC-032: 业务模块可独立启停
- **前置条件**: 平台装载 `order` 与 `invoice` 两个模块
- **测试步骤**: 关闭 `order` → 重启 → 访问其页面与接口
- **预期结果**: 模块未加载、菜单不显示、接口返回「模块未启用」；`invoice` 不受影响
- **类型**: 功能

### AC-033: 扩展点契约测试套件可拦截违规实现
- **前置条件**: 平台提供扩展点契约测试套件
- **测试步骤**: 写一个**故意漏掉租户上下文**的模块实现并接入契约测试
- **预期结果**: 契约测试失败并明确指出缺失项；补齐后通过
- **类型**: 功能 / 安全

### AC-034: 平台小版本升级不破坏扩展点
- **前置条件**: 已有 2 个业务模块实现了扩展点
- **测试步骤**: 平台升级一个小版本 → 跑全部业务模块的契约测试
- **预期结果**: 全部通过，业务代码**零改动**
- **类型**: 可维护性

### AC-035: AI 引导文件体系完整且与实际一致
- **前置条件**: 仓库含 `AGENTS.md`、`prompts/`、`capabilities/`、各模块 `AGENTS.md`
- **测试步骤**: 运行 CI 的引导文件校验（能力索引 vs manifest 汇总、扩展点签名 vs 实际 trait、目录结构合规）
- **预期结果**: 校验通过；人为删除或篡改索引中的权限点后校验**失败**
- **类型**: 功能 / 可维护性

### AC-036: 提示词库可直接产出合规代码
- **前置条件**: `prompts/` 中存在「新建 CRUD 业务模块」提示词
- **测试步骤**: 将该提示词原样交给 AI 助手生成一个模块
- **预期结果**: 产出符合标准目录结构、**直接通过契约测试与 CI**，无需人工重排结构
- **类型**: 功能 / 可维护性

### AC-037: 脚手架生成的模块开箱即用
- **前置条件**: 已安装脚手架
- **测试步骤**: 运行 `create-module`，填写模块名与权限点前缀
- **预期结果**: 生成标准目录 + `manifest.json` + `AGENTS.md` 骨架 + 契约测试接入；生成后**立即可编译运行**
- **类型**: 功能

### AC-038: 能力索引有效防止 AI 重造轮子
- **前置条件**: 能力索引已生成，且索引如实区分「已有能力」与「尚未实现」
- **测试步骤**:
  1. 读 `capabilities/index.json` 的 `already_provided` 与 `not_yet_provided` 两段
  2. 逐项核对：`already_provided` 的每项在源码里**确实存在**对应实现；
     `not_yet_provided` 的每项**确实尚未实现**
- **预期结果**: 索引**不把「尚未实现」写成「已有」**。例如 `@base/ui` 的表格组件、`@base/schema` 渲染器、
  `can()` 权限判定在 REQ-004 交付时点尚未落地（属 REQ-011 / REQ-012），必须出现在 `not_yet_provided` 而非 `already_provided`
- **类型**: 功能 / 可维护性
- **范围说明（BA 决策 2026-11-18，Dev 实施后修订）**: 原 AC 期望 AI 复用 `@base/ui` 表格与 `@base/schema` 渲染器，
  但两者在 REQ-004 交付时点**尚不存在**（分别属 REQ-011 / REQ-012），本期无法验证。
  收窄为「索引如实区分已有与未实现」—— 这才是本期可判定、且真正防住「AI 照着不存在的 API 写代码」的部分。
  **等 REQ-011 / REQ-012 落地后，本条 AC 扩展回原意**（AI 产出复用 `@base/ui` 与 `@base/schema`，
  不重复实现分页/表格/权限判定），届时由 REQ-011 / REQ-012 的用例承载。

### AC-039: 一条命令起全栈
- **前置条件**: 全新克隆的仓库
- **测试步骤**: 执行约定的启动命令
- **预期结果**: 前后端 + PostgreSQL + Redis + 种子数据全部就绪，无需手工执行初始化脚本
- **类型**: 功能

## 需求描述

让第三方应用能安全接入底座，并作为工作台入口被用户使用。

本需求是 REQ-001「通用项目底座」的拆分子项，负责其中的一个能力域。

## ⚠️ 与 REQ-022 的范围划分（D109 —— 跨需求改动显式声明）

> **2026-11-20**：本文件 rev 1 写的「应用注册表：app_id / secret、类型、回调地址、令牌有效期」
> 与「用户授权同意页」**与 REQ-022 直接重叠**。REQ-022 的规格定稿后，
> 按 **D109**（跨需求的包改动必须在 demand 的依赖段显式声明）改写。

| 能力 | 归属 | 说明 |
|---|---|---|
| OAuth2 client（`client_id` / `client_secret` 摘要 / 回调白名单 / 授权类型白名单 / scope 白名单 / 有效期） | **REQ-022** | 协议级对象。表 `platform_oauth_client` |
| 授权同意动作、同意记录、授权撤销 | **REQ-022** | 表 `platform_oauth_grant`；同意页在 REQ-022 |
| 「我的授权」页（用户视角） | **REQ-022** | 用户看自己已授权哪些应用 + 撤销 |
| 令牌签发 / 内省 / 撤销 / 单点登出 | **REQ-022** | OAuth2 授权服务器 |
| **应用注册表**（业务级属性：类型 / 图标 / 描述 / 分类 / 排序） | **REQ-016** | **引用** `platform_oauth_client`，**扩展**而非复制 |
| **应用级权限声明**（向用户展示这个应用要什么权限） | **REQ-016** | 展示层；实际授权动作在 REQ-022 |
| **工作台 / 应用市场**（统一入口、常用应用、最近访问） | **REQ-016** | |
| 前端运行时可扩展的应用路由注册表（ADR A4） | **REQ-016** | |

> **本需求不再自带一份 secret / 回调地址 / 令牌有效期** ——
> 那是 REQ-022 的 client 表。本需求只存「应用长什么样」，
> 敏感字段**一律引用** REQ-022 的 client。

## 功能要求

- **应用注册表**：在 REQ-022 的 client 之上扩展业务属性
  （类型 / 图标 / 描述 / 分类 / 排序 / 归属租户）；
- **应用级权限声明 + 授权管理**（**管理员视角**：管理已注册的应用）；
- **工作台 / 应用市场**：统一入口、常用应用、最近访问；
- 前端运行时可扩展的应用路由注册表（ADR A4）。

## 不在范围内

- 微前端容器实现（ADR A4 明确暂不实现）
- **OAuth2 授权服务器本身**（REQ-022）
- **用户授权同意页**（REQ-022）
- **「我的授权」页**（REQ-022 —— 用户视角）

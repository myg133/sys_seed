## ⚠️ 本用例集的已知能力边界

1. **静态用例占 19/38**：它们能证明「没做错」，但**不能证明「功能真的能用」** ——
   后者由 AC-S-189 的 8 条 HTTP 用例 + AC-S-192 的 2 条 E2E 承担。
2. **E2E 只有 2 条**：这是「最小业务」的必然结果。若实现时交互变多，用例数会增长
   —— 届时**同步更新本索引**。
3. **两条用例依赖尚未存在的平台能力**：
   - TC-020-025（通知落库）依赖 **D354** 的 `DbNotificationSender`；
   - TC-020-037/038（E2E）依赖 **D356** 的前端页面 + shell 路由。
   若这些前置没做，对应用例**判不了**（不是「通过」）。
4. **`BASE_IMPL` / `BASE_UPGRADE` 取错会让 001/031 永远通过** ——
   交付摘要里必须写死两个 sha。

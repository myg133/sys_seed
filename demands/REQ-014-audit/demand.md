## 需求描述

所有敏感操作可追溯、不可篡改，并提供查询界面。

本需求是 REQ-001「通用项目底座」的拆分子项，负责其中的一个能力域。

本轮交付的是**平台的审计基础设施**：一张 append-only 的审计表、一条按租户分段的哈希链、
一个统一的埋点入口、一套查询/校验/归档能力，以及平台自己的登录审计与权限变更审计。

**业务方写业务代码时不需要自建审计表** —— 平台提供统一入口，业务模块声明事件即可。

## 功能要求

### 1. 审计写入

- 一次敏感操作产生**一条**审计记录，字段固定（`api-conventions v1` C12）：
  `id` / `tenant_id` / `actor_id` / `action` / `object_type` / `object_id` /
  `before` / `after` / `ip` / `user_agent` / `created_at` / `prev_hash` / `hash`
- 变更前后值用 JSON 文本承载；无前后值时为空
- 来源 IP 与设备（UA）必须能取到；取不到时**落空串而不是缺列**

### 2. 不可篡改

- 表**只允许 INSERT**，不允许 UPDATE / DELETE（**权限层面**禁止，不是应用自律）
- 记录之间用哈希链链接：`hash = sha256(prev_hash + 规范化事件体)`
- 链**按租户分段**（见 [decisions.md](decisions.md) D130）
- 校验时重算哈希并比对；篡改任一条目必须被检出并**告警**

### 3. 统一埋点入口

- 平台提供**一个**通用审计事件类型 + 一个 sink trait（`platform-core`）
- 业务模块**声明**事件（已有的 `Auditable` / `AuditEventSpec` 声明面保留），
  由平台落库；业务模块**不手工写审计表**
- `platform-org` 与 `platform-iam` 已有的 recorder **不破坏**（保持向后兼容），
  用适配器桥接到平台 sink

### 4. 登录审计

- 本地登录：成功、失败**各一条**，含 IP 与 UA；失败时**不含**密码/令牌
- SSO 登录：已有的 `iam.sso.login.succeeded` / `iam.sso.login.failed` 事件**真正落库**

### 5. 权限变更审计

- 授予权限、撤销权限、创建角色、删除角色各产生一条审计记录，含 `before` / `after`

### 6. 保留策略与归档

- 保留期可配置；超出在线保留期的记录搬入**归档表**
- 归档表同样 **append-only**
- 归档动作**显式触发**（管理接口 + 命令行），**不引入**常驻调度器

### 7. 查询

- 后端查询接口：分页 + 多维过滤（操作人 / 动作 / 对象类型 / 对象 ID / 时间区间）
- 租户隔离由数据库强制，**不是**应用层过滤
- 前端审计查询页面：列表、分页、过滤、字段展示

## 不在范围内

- **数据导出审计** —— 导出能力本身尚未交付（属 REQ-018 / 报表域）；
  统一埋点入口本轮交付后，导出模块落地时自行接入
- **实时告警通道**（短信/邮件/webhook）—— 属 REQ-015 通知
- **后台定时归档调度器** —— 本轮用显式触发代替（见 [decisions.md](decisions.md) D137）
- **审计事件的自定义脚本 / 规则引擎** —— 底座不预置
- **SAML / CAS 审计** —— SAML、CAS 本项目不交付（D124 范围收窄）

# 登录审计（AC-S-127）

- **覆盖 AC**: AC-S-127（10 条：TC-014-051 ~ 060）
- **前置基线**:
  - 测试库 `base_test`；租户 `t-audit`（T-A）
  - 本地账号 `u-1`（密码 `Aud1t-pass`）；一个已配置的 SSO provider
  - 每次登录前记录 T-A 的审计记录总数
  - ⚠️ **每次登录请求都要显式带 `X-Forwarded-For` 与 `User-Agent`**，否则 `ip` 是空串（见下）
- **实现事实（用例按此写）**:
  - 本仓登录侧的 IP **唯一来源**是请求头 `x-forwarded-for`（取第一跳）：
    `crates/platform-iam/src/http.rs:265-273` —— `header_value(headers, "x-forwarded-for")`
    `.and_then(|v| v.split(',').next()…)`，**取不到就是空串**（`unwrap_or_default()`）
  - `user_agent` 来源是 `user-agent` 请求头（`http.rs:270`），同样取不到就是空串
  - 登录 handler 需要租户上下文（`TenantContext(ctx)`，`http.rs:592-597`）→
    失败登录也有确定的 `tenant_id`
  - SSO 事件码已存在：`iam.sso.login.succeeded` / `iam.sso.login.failed`
    （`crates/platform-iam/src/sso/audit.rs:40`、`:42`）
  - SSO 成功事件的载荷键白名单：`{provider, external_id, user_id, ip, user_agent}`（`sso/audit.rs:135`）
  - 本地登录的 IP/UA 在 `RequestMeta`（`crates/platform-iam/src/service.rs:73-80`）；
    而 D140 要给 `RequestContext` 加 `client_ip` / `user_agent`
    → **两套取值来源**，AC 必须指定审计行里的 `ip` 取自哪一个（见挑刺 S-05）

### TC-014-051: 本地登录成功 → **恰好 1 条** `iam.login.succeeded`

- **关联 AC**: AC-S-127
- **前置条件**: T-A 现有审计记录数 `N0`；账号 `u-1` 存在且启用
- **测试步骤**:
  1. 记录 `N0 = SELECT count(*) FROM platform_audit_log WHERE tenant_id='t-audit'`
  2. 用正确密码本地登录一次（带 `x-tenant-id: t-audit`、`X-Forwarded-For: 203.0.113.9`、
     `User-Agent: qa-agent/1.0`）
  3. 查 `SELECT count(*) FROM platform_audit_log WHERE tenant_id='t-audit' AND action='iam.login.succeeded'`
- **预期结果**:
  1. 登录返回 `200`（含 access token）
  2. 步骤 3 的计数 `== 1`
  3. 该条 `tenant_id == 't-audit'`、`actor_id == 'u-1'`
- **类型**: 安全
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 基本路径
- **备注**: 事件码 `iam.login.succeeded` 取自 design §6.1 的埋点表。〔S-15〕

### TC-014-052: 本地登录失败 → **恰好 1 条** `iam.login.failed`

- **关联 AC**: AC-S-127
- **前置条件**: 同 TC-014-051
- **测试步骤**:
  1. 用**错误**密码本地登录一次（同款请求头）
  2. 查 `action='iam.login.failed'` 的条数
- **预期结果**:
  1. 登录返回 `401`（**不是** 500）
  2. 步骤 2 的计数 `== 1`
  3. 该条 `actor_id IS NULL`（**未认证，没有操作人**）
  4. 该条 `tenant_id == 't-audit'`（**失败也有租户** —— 由请求的租户标识确定）
- **类型**: 安全
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 基本路径 + 边界（未认证）
- **备注**: decisions.md D132 明写「登录**失败**时租户由请求的租户标识确定，此时 `actor_id` 为空但 `tenant_id` 已知」。
  第 3、4 条是这个决策的机械化。

### TC-014-053: SSO 登录成功 → **恰好 1 条** `iam.sso.login.succeeded`

- **关联 AC**: AC-S-127
- **前置条件**: 一个已配置的 SSO provider；已绑定的 SSO 账号
- **测试步骤**:
  1. 走一次 SSO 登录成功流程
  2. 查 `action='iam.sso.login.succeeded'` 的条数
- **预期结果**:
  1. 步骤 2 的计数 `== 1`
  2. 该条 `object_type` 指向 SSO 主体（**具体值按实现约定逐字断言**）
  3. 该条 `before` 为 `NULL`、`after` **不含** `client_secret` / `code` / `access_token`
- **类型**: 安全
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 基本路径
- **备注**: 事件码已存在（`sso/audit.rs:40`），本轮只是**桥接到平台 sink 真正落库**
  （REQ-013 的 AC-S-108 只验「声明 + 发出」，TC-013-127 反向断言过「没有审计表」）。
  ⚠️ SSO 侧载荷的键白名单是 `{provider, external_id, user_id, ip, user_agent}`
  （`sso/audit.rs:135`）→ `object_type` / `object_id` 装什么**规格没定** → 需 BA 拍板。〔S-15〕

### TC-014-054: 三条登录审计**均含非空** `ip` 与 `user_agent`

- **关联 AC**: AC-S-127
- **前置条件**: 同 TC-014-051/052/053；三个请求都带 `X-Forwarded-For: 203.0.113.9` 与 `User-Agent: qa-agent/1.0`
- **测试步骤**:
  1. 执行成功登录、失败登录、SSO 登录
  2. 读三条记录的 `ip` 与 `user_agent` 列
- **预期结果**:
  1. 三条的 `ip` 都 `== "203.0.113.9"`（**非空且逐字相等**）
  2. 三条的 `user_agent` 都 `== "qa-agent/1.0"`（**非空且逐字相等**）
- **类型**: 安全
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 基本路径
- **备注**: ⚠️ **这条必须显式带请求头**。本仓 `ip` 的唯一来源是 `x-forwarded-for`
  （`crates/platform-iam/src/http.rs:267`），普通本地登录**不带**该头 → `ip` 为**空串**。
  AC 原文「上述三条均含**非空**的 `ip`」按字面（不发 `X-Forwarded-For`）执行 → **不可达**。〔S-05〕

### TC-014-055: `ip` 精确等于 `X-Forwarded-For`

- **关联 AC**: AC-S-127
- **前置条件**: 同 TC-014-054
- **测试步骤**:
  1. 用 `X-Forwarded-For: 203.0.113.9, 198.51.100.7` 发起一次登录
  2. 读该条审计记录的 `ip`
- **预期结果**:
  1. `ip == "203.0.113.9"`（**第一跳**；不是整串、不是最后一跳、不是第二跳）
  2. `ip != "198.51.100.7"`
- **类型**: 安全
- **优先级**: P1
- **自动化**: 可自动化
- **设计方法**: 边界值（多跳）
- **备注**: 取值口径与既有实现一致（`http.rs:267-269` `.split(',').next()`）。
  这条同时把「ip 是**哪一跳**」钉死 —— 既有实现的这个口径**没有**写进 REQ-014 规格。

### TC-014-056: 无 `X-Forwarded-For` 时 `ip` 落**空串**（不是缺列、不是 `null`）

- **关联 AC**: AC-S-127
- **前置条件**: 同 TC-014-051
- **测试步骤**:
  1. **不带** `X-Forwarded-For` 发起一次登录（带 `User-Agent`）
  2. 读该条记录的 `ip` 列；查列定义
- **预期结果**:
  1. `ip == ""`（**空串**，不是 `NULL`）
  2. 该列存在且 `NOT NULL`（与 TC-014-006 同一判据）
- **类型**: 边界
- **优先级**: P1
- **自动化**: 可自动化
- **设计方法**: 边界值（缺失）
- **备注**: 这条与 AC-S-122「取不到时落**空串**而不是缺列」口径一致。
  AC-S-127 的「非空」只在**显式带了请求头**时成立 → 两条 AC 的口径必须由 BA 明确统一。〔S-05〕

### TC-014-057: 审计记录中**不含**密码字面量

- **关联 AC**: AC-S-127
- **前置条件**: 同 TC-014-052（用错误密码 `Wr0ng-pass!` 登录）
- **测试步骤**:
  1. 用错误密码 `Wr0ng-pass!` 登录一次
  2. 检索 T-A 的全部审计记录**文本**（把所有列拼成一个大字符串）
  3. 在该字符串里搜 `Wr0ng-pass!`
- **预期结果**:
  1. 步骤 3 的命中数 `== 0`
  2. 失败那条的 `before` / `after` 均为 `NULL` 或**不含**密码键
  3. 失败那条的 `action == 'iam.login.failed'`
- **类型**: 安全
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 攻击路径 + 全量扫描
- **备注**: 检索必须**扫全部列拼成的文本**，不能只扫 `before`/`after` —— 密码可能落在 `object_id`、
  `action` 等任意列里。AC 原文说「检索该租户的全部审计记录文本」，本用例把它机械化。〔S-24〕

### TC-014-058: 审计记录中**不含**任何 access / refresh token

- **关联 AC**: AC-S-127
- **前置条件**: 同 TC-014-051；已拿到一次登录返回的 `accessToken` 与 `refreshToken`
- **测试步骤**:
  1. 登录成功一次，记下返回的 access token 与 refresh token
  2. 检索 T-A 全部审计记录文本
  3. 在文本里搜这两个 token 的**完整字面量**
- **预期结果**:
  1. 两个 token 的命中数**都** `== 0`
  2. 同时搜 JWT 的**三段结构**特征（`eyJ` 开头的 header 段）也 `== 0` 命中
- **类型**: 安全
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 攻击路径 + canary
- **备注**: 第 2 条防「token 被截断/改写后仍混进去」。canary 用**真实**的登录返回 token，
  不是编造的 —— 编造的 token 不在数据里，扫描器就永远 0 命中。

### TC-014-059: 失败登录的审计**不泄露**账号是否存在（成功/失败载荷可区分但不含账号名）

- **关联 AC**: AC-S-127
- **前置条件**: 两个账号：`u-1`（存在）与 `u-ghost`（不存在）；两次都用错误密码
- **测试步骤**:
  1. 用 `u-1` + 错误密码登录一次
  2. 用 `u-ghost` + 错误密码登录一次
  3. 读两条失败审计记录的全部列
- **预期结果**:
  1. 两条都产生记录，`action` 都是 `iam.login.failed`
  2. 两条记录的**字段集合相同**
  3. 两条记录都**不含** `u-ghost` 这个字符串
  4. 两条记录的 `object_id` 都是 `NULL`（或都不含用户名）
- **类型**: 安全
- **优先级**: P1
- **自动化**: 可自动化
- **设计方法**: 等价类（存在 vs 不存在）
- **备注**: 失败审计是最容易成为**账号枚举**侧信道的出口。AC-S-127 只说「不含凭据」，
  没禁「含用户名」。本条按「失败记录不含用户名」写；若 BA 要保留用户名，需明确豁免并说明理由。

### TC-014-060: 审计写入失败**不得**把登录变成 500（且顺序固定）

- **关联 AC**: AC-S-127
- **前置条件**: 能让审计写入失败（如让审计表不可写 / 用敏感键触发拒绝 / 断开审计库连接）
- **测试步骤**:
  1. 制造一次审计写入失败
  2. 用正确密码登录一次
  3. 读 HTTP 状态码与响应体
- **预期结果**:
  1. 状态码**不是** `500`
  2. 状态码**不是** `200`（**审计没写成就不该当成功**）→ 期望 `401`/`503`/`500` 中的哪一个
     **由 BA 拍板**（见挑刺 S-29）
  3. 响应体是 RFC 9457 ProblemDetails（有 `code` / `trace_id`），**不是**裸 500 文本
- **类型**: 安全
- **优先级**: P1
- **自动化**: 可自动化
- **设计方法**: 异常路径
- **备注**: 「审计失败时登录怎么办」是**取舍**：放行 = 有登录无审计；拒绝 = 有审计无登录。
  AC 没写，本用例把第 2 条标为**待 BA 拍板**（不钉死具体码）。〔S-29〕

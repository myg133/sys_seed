# 审计查询界面（AC-S-132）

> ⚠️ **本文件已按 D169 + 契约 C7 修订**（rev 1 → rev 3 口径，2026-11-20）。
> rev 1 写的「请求带 `page=2`」与「过滤参数 `actorId=…` / `action=…`」**已被推翻**：
> - **分页** → **游标分页**（`?cursor=&limit=`），`page` 与 `cursor` **互斥**（C7）；
>   页码指示用「**游标栈**」实现（前端在内存里维护已访问的 `cursor` 数组），
>   页码指示 = 「**本次浏览**第 N 页」，**不是**「全量第 N 页」（D169）。
> - **过滤** → **通用方括号语法** `?filter[field][op]=value`，
>   `op` 白名单 = `eq` / `ne` / `in` / `contains` / `range`（C7 / D145）。
> - **排序** → 默认 `createdAt DESC, id DESC`（D155）；`id` 作 tiebreaker。
> 〔D169 裁定 Dev-C 的提问：游标算不出全量页码 → 用游标栈保住页码观感，
> 且页码分页在持续追加的审计表上必然重复/遗漏，不能用。〕

- **覆盖 AC**: AC-S-132（10 条：TC-014-111 ~ 120）
- **前置基线**:
  - shell 已启动；测试库 `base_test` 可用且 T-A 有审计数据
  - 一个具备 `audit:events:read` 的账号（`u-auditor`）；一个**无**该权限的账号（`u-noperm`）
  - 前端单测：`apps/shell` 的 vitest（`pnpm --filter @base/shell test`）
  - E2E：`code/e2e/*.spec.ts`（playwright）
- **实现事实（用例按此写）**:
  - 路由表在 `apps/shell/src/lib/routes.ts`；`/admin/audit` 是**新增**路由（design §10）
  - 路由守卫机制（`apps/shell/src/lib/router.ts:204-227`）：
    命中带 `permission` 的路由 → `guard(getState(), route.permission, …)`；
    不放行 → 地址改写成落点（`/403`），**且目标路由的 `load` 不会被调用**
    （`router.ts:244-250`）→ 目标接口的请求计数为 **0**
  - **403 页已存在**：`apps/shell/src/pages/Forbidden.svelte`
    —— 渲染 `<h2>403</h2>` + `common.forbiddenMessage`，`data-testid="forbidden"`
    （`Forbidden.svelte:19-21`）→ **「不是空白页」这条既有做法已经满足**
  - 既有受保护页 `/admin/roles` 的写法（`apps/shell/src/pages/ProtectedRoles.svelte`）：
    数据由路由 `load` 加载；分页用 `@base/hooks` 的 `createPagination({ pageSize: 10 })`
    + `components/Table.svelte`（**客户端分页**，`total={props.roles.length}`）
  - ⚠️ 审计页需要**服务端分页**（契约 C7 的**游标**口径：`?cursor=&limit=`），
    与 `ProtectedRoles.svelte` 的**客户端分页**是**两种模式** → 不能照抄。
  - 契约 C4：权限点编码固定 `module:resource:action`，前端 `can()` 与后端鉴权读**同一份注册表**
  - ⚠️ 游标**只对默认排序有效**：后端对「带游标 + 带任意 `sort`」返回 **400**
    （D179 裁决保留的收紧）→ 前端**默认不发** `sort`（默认排序 `-createdAt` 与后端默认排序等价）。

### TC-014-113: 分页控件**可用**（**游标**口径）

- **关联 AC**: AC-S-132
- **前置条件**: T-A 有 ≥ 5 条记录；页大小 `limit=2`（请求参数 `?limit=2`）
- **测试步骤**:
  1. 进入 `/admin/audit`
  2. 点「下一页」
  3. 读当前页码指示与请求参数
- **预期结果**:
  1. 页码指示从 1 变成 2（文案是「**本次浏览**第 2 页」，不是「第 2 页 / 共 N 页」）
  2. 后端收到的请求参数含 `cursor=<上一页响应里的 nextCursor>` 与 `limit=2`
     （**服务端游标分页**，不是前端切片）
  3. 请求参数**不含** `page`（游标与页码**互斥**，C7；且审计表持续追加，
     页码分页必然重复/遗漏 —— D169）
  4. 表格行的内容**变了**（第 2 页不是第 1 页）
- **类型**: 功能
- **优先级**: P0
- **自动化**: 可自动化
- **设计方法**: 状态迁移
- **备注**: 第 3 条防「照抄 `ProtectedRoles.svelte` 的客户端分页」——
  审计记录量大，必须服务端分页。既有页面的 `createPagination` 是客户端分页（`total={props.roles.length}`），
  **不能直接复用**。〔S-35〕
  ⚠️ **本条是游标链路的端到端判据**：后端必须返回**非 null** 的 `nextCursor`
  （响应字段名 camelCase，契约 C13），否则前端「下一页」按钮恒为禁用态 → 本条判红。
  〔D169〕

### TC-014-114: 翻页后记录**不重复**

  ⚠️ AC 没有定义列表排序 → 后端默认排序固定为 `createdAt DESC, id DESC`（D155），
  `id` 作 tiebreaker → 并列时也不会重复/遗漏。〔S-11〕

### TC-014-117: 前端过滤结果与**后端接口**结果**一致**

- **关联 AC**: AC-S-132
- **前置条件**: 同 TC-014-115
- **测试步骤**:
  1. 在前端按操作人过滤，读表格里的记录 id 集合
  2. 用**同一过滤条件**直接调 `GET /api/audit/events?filter[actorId][eq]=<同一值>`
  3. 比对两边的 id 集合
- **预期结果**:
  1. 两边的 id 集合**完全相等**
  2. 两边的 `total` 相等
- **类型**: 功能
- **优先级**: P1
- **自动化**: 半自动
- **自动化理由**: 需要**同时**驱动浏览器 UI 与后端接口并比对两边结果，
  在单测里要跨两个世界取值。E2E 里可以做（前端取 DOM、后端取 `request` 响应），
  但需要真实的登录态与夹具 → 归到 E2E 层更合适，故标半自动。
- **设计方法**: 交叉验证
- **备注**: AC 原文「结果与后端接口一致」—— 这条是**防止前端自说自话**的关键，
  不能只断言「页面上有东西」。

### TC-014-120: E2E **不使用** `skip`（除非被测系统未就绪）

- **关联 AC**: AC-S-132
- **前置条件**: E2E 环境就绪
- **测试步骤**:
  1. 跑审计页的 E2E 用例
  2. 检查输出里的 `skipped` 计数
  3. 检查用例源码里有没有 `test.skip` / `skip(` 之类的条件跳过
- **预期结果**:
  1. `skipped` 计数 `== 0`
  2. 源码里**没有**针对「无权限」「403」「数据为空」这类**预期结果**的 `skip`
  3. 若存在 `skip`，其条件**只**是「被测系统未就绪」（服务没起来、数据库没就绪）
- **类型**: 功能
- **优先级**: P0
- **自动化**: 半自动
- **自动化理由**: 「源码里有没有 skip」是**人工审查**项，机械扫描只能给出候选位置，
  判断「这个 skip 是否合规」要人看。判据（`skipped == 0`）本身可自动化。
- **设计方法**: 纪律守卫
- **备注**: dev-guide §9.9 + D108：「E2E 的 `skip` **只允许**「被测系统未就绪」；
  夹具 / 授权不对必须 **fail**」。
  REQ-013 的复验里出现过「阳性对照恒真断言」被当成通过的教训 ——
  本条要求 E2E 里 403/空态**必须 fail 而不是 skip**。

## 本需求自有 AC

### AC-S-001: 目录规范可校验
- **前置条件**: 存在一个不符合 `modules/<name>/` 约定的目录
- **测试步骤**: 1. 在 `modules/` 下建一个缺 `manifest.json` 的目录 2. 运行 CI 的目录规范校验
- **预期结果**: 校验失败并明确指出缺失的文件；补齐后通过
- **类型**: 功能

### AC-S-002: 工具链版本锁定
- **前置条件**: 无
- **测试步骤**: 1. 在一台全新机器上 clone 仓库 2. 执行 `bun install` 与 `cargo build`
- **预期结果**: 无需手工安装 Rust/Bun/PostgreSQL 即可构建；版本由仓库内的锁定文件固定
- **类型**: 功能

### AC-S-006: 低配开发基线生效
- **前置条件**: 目标机器 8 线程 / 7.7G 内存 / 4.9G 可用 / 8G swap（i7-8550U）
- **测试步骤**: 1. 按 `.cargo/config.toml` 执行冷编译 `cargo build` 2. 执行 `cargo build --tests` 3. 观察峰值内存与耗时
- **预期结果**: 冷编译峰值内存 < 2.5G、全程不因换页而卡死；`cargo check` 峰值 < 1.5G；不出现 OOM
- **类型**: 性能

### AC-S-007: 日常命令可在低配机流畅执行
- **前置条件**: 依赖已编译过一次
- **测试步骤**: 1. 改一行 Rust 代码 2. 执行 `cargo check` 3. 执行 `cargo test --lib`
- **预期结果**: `cargo check` < 60 秒；`cargo test --lib` < 3 分钟；两者均无需关闭其他服务
- **类型**: 性能

### AC-S-008: 前端开发不依赖后端常驻
- **前置条件**: 后端未启动
- **测试步骤**: 1. 仅启动 Vite 前端 2. 运行前端单测与 E2E 3. 在测试全程采样 Rust 进程数
- **预期结果**: 前端可独立启动与测试；测试期间 Rust 进程数恒为 0；后端未提供任何数据也不影响前端链路
- **类型**: 功能 / 性能
- **范围说明（BA 决策 2026-11-18，QA 复核后收窄）**: 本期只验「前端链路不依赖后端常驻」。
  原 AC 里的 **MSW mock、列表页、表单页、分页/校验/权限显隐的 mock 数据**下推：
  - MSW 与 mock 数据设施 → **REQ-011 前端 SDK 骨架**
  - 列表页 / 表单页的通用渲染 → **REQ-012 元数据驱动渲染**（依赖 `@base/schema` 渲染器，本期尚不存在）
  理由：本期要求实现它们等于提前做 REQ-011/012 的活，属超范围。
  收窄后 AC-S-008 仍能证明「前端开发不需要 Rust 后端常驻」这一核心目的。

### AC-S-009: rootless podman 本地环境可用
- **前置条件**: 已安装 podman 与 podman-compose，无 root 权限
- **测试步骤**: 1. 执行 `podman-compose up -d` 2. 用 `psql` 连 `base_dev` 与 `base_test` 3. 执行 `podman stats --no-stream`
- **预期结果**: 两个库均可连接；PostgreSQL + Redis 容器**合计常驻内存 < 250M**；全程无需 root 权限
- **类型**: 功能 / 性能

### AC-S-010: 集成测试不使用 testcontainers
- **前置条件**: 已有本地 `base_test` 库
- **测试步骤**: 1. 运行集成测试套件 2. 观察容器数量变化
- **预期结果**: 测试全程**未新建任何容器**；测试前后 `podman ps` 数量不变；测试库被重置而非新建
- **类型**: 性能 / 可维护性

把「**谁能看到什么、能做什么**」从业务代码里抽出来，变成平台统一判定的数据，
并让权限点注册表成为前后端**同一份**事实来源。

本迭代是底座里**第一个真正的「判定」模块** —— 前两个迭代（Sprint 1 地基、Sprint 2 身份）

> 比自己反复读一遍文档有效得多。成本是 BA 多改两轮文档，收益是少两轮返工。

## 迭代出口标准

| 出口标准 | 状态 | 证据 |
|---|---|---|
| 权限点注册表双向对账，不一致即**启动失败** | ⬜ | 造「manifest 多一个 / 库里多一个」两种违规，进程起不来且逐条列出差异 |
| 数据范围 5 种语义在**真实库**上求值正确 | ⬜ | 五种 scope 各列**逐条记录 id** 的期望集；五个探针用户 |
| 兼岗默认主部门，取并集须显式开启 | ⬜ | 兼岗用户的 `OWN_ORG` 结果**不含**兼职部门任何一条 |
| 主部门缺失 / 歧义 → **fail closed 到 SELF** | ⬜ | 预防层（DB 拒绝）+ 防御层（绕过约束造歧义）**两层都测** |
| 多角色 scope 取**最宽松**（并集语义） | ⬜ | 解绑第三个角色后结果**必须变窄**（区分并集 / 交集） |
| 鉴权三语义：401 / 403 / 404 | ⬜ | 缺权限点 → 403 `INSUFFICIENT_PERMISSION`；超范围 → 404 `NOT_FOUND` |

| 数据范围过滤在 **SQL 层**生效 | ⬜ | 断言渲染出的 SQL 含范围条件片段且值走参数绑定 |
| 契约门禁不再常红 | ⬜ | `scripts/sync-contracts.sh` 退出 0（当前 develop 上是 exit 2） |
| 依赖预算不增长 | ⬜ | `Cargo.lock` 包数 ≤ **293**（不引策略引擎 / Redis 客户端 / nom） |

## 环境备注（低配机）

- 开发机 8 线程 i7-8550U / 7.7G 内存 / **4.7G 可用** / 磁盘剩 114G
- **Rust 编译串行执行，不并行**（`.cargo/config.toml` 固定 `jobs = 3`）
- 复用 target 目录：`export CARGO_TARGET_DIR=/home/myg133/Projects/system_seed/code/target`
- 日常主力命令 `cargo check`（增量 ~1s）
- 容器用 rootless podman，**不用 docker**（数据库栈 81MB）
- 镜像必须用 `docker.m.daocloud.io/` 显式前缀（docker.io 直连超时）
- 第三方依赖树 **273**（`Cargo.lock` 共 293 包）
- **断电后必须手工恢复**：bus watcher + podman 容器（都不会自启）
  → 见 [dev-guide-low-spec.md](../plan/dev-guide-low-spec.md) §8.5
- ⚠️ `cargo test` **只能有一个 `--`**（双 `--` → libtest 把 flag 当过滤串 → 0 passed 假绿）
- ⚠️ 应用连接**必须用普通角色 `base_app`**（超管会被 `require_isolation` 拒绝启动，退出码 3）

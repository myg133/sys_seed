## 1. 这轮最值得记的三件事

### 1.1 🔴 S-03：我设计的「运行时路由」在现有壳层里**根本做不到**

我在 AC-S-163 里写「运行时加路由就能渲染新页面」。QA 逐条核实后指出**做不到**，
我自己又验了四个事实：

| 事实 | 证据 |
|---|---|
| `RouteDefinition` **无 component 字段** | `router.ts:41-62`（只有 `path`/`title`/`permission?`/`requiresAuth?`/`load?`） |
| `createRouter` **捕获数组引用** | `router.ts:156` `const { routes } = options` |
| `Router` **无 `addRoute` / `setRoutes`** | `router.ts:113` |
| 页面渲染**逐路径硬编码** | `App.svelte:221-266`，**10 个** `{:else if}`，兜底 `<Home/>` |

→ design 里的 `routes = [...createRoutes(...), ...routesFromNavigation(nav)]`
**① 重赋值对路由器零影响；② 新路径也会落到 `<Home/>`；③ 要真生效必须改 `router.ts`（违反我自己的 D270）。**

**根因**：`ADR-0001 D4` 说的「应用 = 路由」**成立**，但那条路由必须是**外部 URL 的整页跳转** ——
第三方应用是**独立站点**（`launch_url`），**没有本 SPA 的组件**，天生不该进 SPA 路由表。
**我把「独立应用」当成了「底座内的一个页面」。**

**处置**（D278）：AC-S-163 降级重写为三条可判判据（纯函数单测 / `external` 整页跳 / `router.ts` 零改动），
并把「不做」显式写进 **AC-S-163.b**，防止后人以为漏了 → **TD-048**。

### 1.2 🟡 S-01 / S-02：两条「能静默坏掉」的配置问题

| 坑 | 后果 | 为什么危险 |
|---|---|---|
| 3 个 `app.*` 配置键漏写 `"scope": "platform"` | 落到 `Tenant` 作用域（`manifest.rs:264-266` 的 `default_scope()`）→ 平台端点直接拒 → **「配置生效」永不可达** | manifest **能解析**、迁移**能写库**、编译**能过**，**只有运行时静默过滤** → 失败现象像业务 bug |
| `config` 段写成裸值（`"app.recentCount": 6`） | `parse_checked` 直接失败 → **服务起不来**，且日志写「权限点对账失败」→ **误导排查方向** | 一个格式错误伪装成另一个领域的错误 |

→ D276 / D277，并在 design 里写明「照抄 `platform-oauth/manifest.json` 的形状」。

### 1.3 🟢 依赖「既有 API 的直觉」必须被代码推翻

我在 AC-S-165 里凭「新增一个 Rust crate → 索引多一个文件」的直觉写了「`capabilities/` 15 个文件」。
**实测推翻**：生成器（`xtask/src/capabilities.rs:57-79`）是**按类别**组织的，
新增 crate 只让 `permissions.json` 多一个 `modules[]` 条目 → **文件数仍是 14**。

→ 立 **D275**：**AC 里任何数字必须有 `file:line` 或实测命令支撑**。

**这轮我在这条规则上错了 3 次**（capabilities 15 / TITLES 101 / 端点数 8-vs-10），
每次都是「凭直觉写一个数，然后没人会去验它」。

## 3. 值得记的两个「自我纠错」（子 Agent 自己抓的，不是 BA 抓的）

### 3.1 棒 2：变异发现一条判据**零区分力**

它做「去掉 `displayName` 次级排序」的变异时发现只红 1 条 —— 因为渲染测试的**输入顺序恰好等于期望顺序**（稳定排序会原样保留）。改成 `D, C` 后红 2 条。

**若不跑变异，这条会以「已覆盖」进报告** —— 正是 REQ-022 栽的坑。

### 3.2 棒 1：把「id 与 displayName 刻意反序」写进夹具

`app_real_stack.rs:558` 的注释：

> 「**id 与 displayName 顺序刻意相反**（`app-z`→"C 应用"、`app-a2`→"D 应用"）：
> 让『按 id 兜底』的实现得到 D→C（错），只有按 displayName 才是 C→D（对）
> → 否则次级排序键删掉也测不出来」

**这是「让错误实现必然得到错误结果」的正面样本** —— 比「有断言就行」高一个层次。

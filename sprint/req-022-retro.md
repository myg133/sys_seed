## 1. 这轮唯一真正的教训

### 1.1 🔴 「形式上的 22 行」≠「实质上的 22 次核对」

**我做了什么**：拿到 22 条 AC，逐条想「哪条测试覆盖它」，把测试函数名填进去。
**看起来**每条都有落点。**实际上**我填的很多东西在测试源码里根本不存在：

| 我写的「判据落点」 | `grep` 的真相 |
|---|---|
| 「401 `UNAUTHENTICATED`，不含 `error` 键」 | 只调了 `iam.verify_access_token()` **这个函数**，两个业务端点**一次没打** |
| 「`sid` 齐全、`events` 含 backchannel 键、无 `nonce`」 | 该字符串在测试里 **0 命中** |
| 「测试侧独立 ES256 验签」 | 测试里唯一相关文字是注释「**只解，不验签**」 |
| 「哈希链 `ok = true`」 | 用的是**内存假 sink**（`RecordingSink(Arc<Mutex<Vec<…>>>)`），**不落库** |

**根因**：我是**从 AC 出发**（"这条 AC 要求什么 → 哪条测试大概覆盖了它"），
而不是**从测试出发**（"这条测试的 `assert!` 到底断什么 → 它能证明哪条 AC"）。

**改正**（已写进 `dev-guide §9.15`）：
- 判 AC 前**先 `grep` 你要断言的字符串**；
- 表格**每一格必须能指到 `file:line` 的 `assert!`**；
- AC 的核心承诺涉及「行为」而非「字段」时，**判据必须打到端点/接口上**。

### 1.2 🟡 四类最容易被「看起来有」蒙过去的判据

这轮的 7 条阻塞级，全部落在这四类里：

| 类型 | 症状 | 本轮的实例 |
|---|---|---|
| **测函数不测端点** | 「端点默认拒绝 X」→ 测试调的是底层函数 | AC-S-151 |
| **假 sink / 假 DB** | 「审计落库」→ 用的是内存 `Vec` | AC-S-154 |
| **字段断言代替验签** | 「ES256 签名有效」→ 只断了 `alg` 字段 | AC-S-145 |
| **无区分力的夹具** | 「用 `{授权页基址}`」→ 夹具里两者**恰好相等** | AC-S-134 |

### 1.3 🟢 独立复核**真的**救了这个需求

如果按我原来的 22/22 合并，那 7 条阻塞级会带着**零覆盖**上线 —— 而它们恰恰是**安全承诺**：
- 「底座业务端点默认拒绝第三方 OAuth 令牌」（AC-S-151）
- 「令牌是 ES256 签的，第三方可凭 JWKS 自行验签」（AC-S-145）
- 「私钥泄露也拿不到越权令牌」（AC-S-146）

→ **流程强制项「修复轮后必须有独立复核」本轮兑现了它的全部价值。**

## 2. 其它值得记的

### 2.1 修了一个「第一次失败、重试就好」的真 bug（TD-047）

`platform-oauth` 的 `authenticate` 中间件**漏调 `PermissionRefresher::ensure_fresh`**。
`RbacChecker::has` 是纯缓存查询（缓存无该用户 → fail closed 直接 false），
而填缓存是**异步**的 → 用户第一次打受保护端点**必然 403**、第二次就好。

⚠️ **棒1 的 117 个测试全绿也没抓到**（集成测试用内存 `PermissionTable`，没有 epoch 缓存这回事）
→ **只有真服务 + 真 E2E 才能暴露**。这是终版 E2E 存在的价值的直接证据。

### 2.2 前端的「点击链」只能靠 E2E 兜（无 DOM 测试环境）

`OAuthDevice.svelte` 的 `userCode` 状态**从未从 URL 赋值** → 设备码页点「允许」**什么都不发**。
`svelte-check` 0 error + **279 个前端测试全绿**都没抓到（没有 DOM 环境，测不到点击）。

→ 我当时的裁定「接受无 DOM 环境、但 E2E 必须真点按钮」是**对的**，
而且我在终版清单里把它写成了**必查项** —— 这条必查项抓到了这个 bug。

### 2.3 我自己的变异建议错了，Dev 纠正了我

我建议「RLS 变异：把 `WITH CHECK` 去掉」。**在 PostgreSQL 里这无效** ——
没有 `WITH CHECK` 的 policy，`USING` 表达式会**同时**用作 INSERT/UPDATE 的检查条件。
→ 棒1 实测发现后改用 `WITH CHECK (true)`，独立复核又**本地实测确认**了棒1 是对的。

**教训**：BA 给的变异点也要**先验证它在语义上成立**，否则「变异不红」会被误读成「判据没区分力」。

### 2.4 一条「守门断言」的自律

修复轮 Dev 在写 AC-S-149 的日志判据时，发现实现把**投递 URI** 塞进了名为 `client_id` 的字段。
它的处理是：断言「日志**不含** clientId」，并在注释里写
「**若哪天修了，这条断言会变红并提示同步更新报告**」。

我后来真的修了 → 那条断言**立刻变红**，正如它的注释预言。
→ **这种「为未来的修复预留红点」的写法值得推广**：它让「已知偏差」不会悄悄变成「永久偏差」。
